# ChatGPT8: автоматические строительные стадии на сервере

Дата: 15 ноября 2026. Ветка: `ChatGPT8`, коммит `c89d465c5d5e03b8c9dde848d8cb196f24ea9433`.

## Реализация

- Общий модуль `server/construction_stages.py` для SQLite и PostgreSQL, с хранением `construction_stages(object_id,stage,next_at)` и внешним ключом на `buildings`.
- Новая PostgreSQL-миграция `006_construction_stages.sql`; SQLite создаёт таблицу через `_prepare`.
- Новые здания получают авторитетную стадию `foundation`. Через `step_seconds` переходят в `frame`, затем через второй интервал в `complete`.
- **Исправлено при слиянии (Claude):** в ветке длительность стадии была зашита как 2 ч 20 мин (в предположении «1 игровой месяц = 14 часов»), что противоречит часам проекта (`LUNEX_MONTH_SECONDS`, по умолчанию 86400) и ломало инвариант «длина месяца не меняет экономику» (два теста `tools/test_balance_sim.py`). Теперь **одна стадия = 1/6 игрового месяца** при любой длине месяца (по умолчанию 4 часа), переопределение `LUNEX_CONSTRUCTION_STEP_SECONDS` осталось. Параметр `LUNEX_CONSTRUCTION_STEP_SECONDS` от 1 до 86400 позволяет изменить длительность для тестирования/настройки без правки кода.
- Продвижение происходит **лениво при запросах /events и /chunk** с серверным временем, в транзакции под мировым lock; если сервер простаивал, просроченные стадии догоняются сразу, без отдельного фонового демона.
- Каждое изменение стадии публикует `building_created` с `construction_stage` и тем же `object_id` и footprint, повышает версии соответствующих чанков. Клиент `world.gd` уже умеет перестраивать GLB по изменённой визуальной сигнатуре.
- Старые здания без записи в `construction_stages` отображаются как `complete`; миграция не переводит их обратно на фундамент.
- Повторные вызовы не дублируют события после завершения; при пропуске двух интервалов состояние догоняется до `complete`.

## Ограничения

- Это **серверная синхронизация визуальных стадий**, не полный симулятор стройки. Текущая экономика регистрирует здание и его производственную запись при строительной команде, не ожидая завершения визуальных стадий. Для запрета производства до сдачи нужен отдельный согласованный рефакторинг экономики и миграции.
- При отсутствии запросов к `/events` или `/chunk` отдельный таймер не выполняет записи; при следующем запросе сервер автоматически догоняет стадии.
- Длительность по умолчанию является настройкой реализации, а не ранее утверждённым сроком строительства для каждого типа здания.
- Реальный запуск обновлённого Android APK на устройстве и GitHub Actions cloud run здесь не подтверждены.
