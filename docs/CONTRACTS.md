# Контракты между игроками

Прямые сделки на мёд, нефть и товары **мимо общего рынка**. Числа — настройки в `server/economy.py` (блок `CONTRACT_*`). Сервер — единственный источник истины: клиент не назначает цену сделки сам по себе, он только предлагает значения, которые сервер проверяет.

## Доска предложений

Игрок-поставщик создаёт **предложение**:

| Поле | Смысл | Предел |
|---|---|---|
| `product` | `honey`, `oil` или `goods` | только эти три |
| `qty` | единиц **в месяц** | 1…10 000 |
| `price` | рублей за единицу, целое | 50–200 % **базовой** (reference) цены продукта |
| `term_months` | срок в игровых месяцах | 1…24 |
| `penalty` | штраф поставщику за **каждую** недопоставленную единицу, рублей | 0…`price` |

Покупатель принимает предложение целиком. После принятия предложение с доски снимается и появляется **активный контракт**. Первый исполняемый месяц — текущий игровой месяц (когда он завершится), последний — `start + term − 1`.

Ограничения:

- не больше **6 открытых** предложений на игрока и **6 активных** контрактов (считаются и поставки, и закупки);
- нельзя принять своё предложение;
- NPC (`npc:*`) и город (`city`) не участвуют;
- команда идемпотентна по `request_id` (повтор возвращает тот же ответ и не создаёт второй контракт).

## Исполнение (месячный шаг)

В `production.step_month`, **до** очистки рынка по этому продукту:

1. Свой завод поставщика резервирует сырьё первым (правило «сначала своё» не ломается).
2. Свободный остаток (склад, затем выпуск) уходит покупателю по контрактам в порядке `id`. Сколько не хватило — недопоставка.
3. Поставленное покупателю лежит на его складе **до** его собственного потребления, поэтому завод покупателя тратит его как своё сырьё и не покупает этот объём на рынке.
4. На рынок попадает только то, что осталось. Спрос рынка на это сырьё тоже меньше: заводу оно уже не нужно. Объём, который покупатель не потребил и не удержал складом, продаётся по обычным правилам склада (без склада — сразу на рынок).

Деньги — **после** месячных проводок рынка, отдельными сбалансированными проводками «покупатель → поставщик» (`kind=contract`) и «поставщик → покупатель» за штраф (`kind=contract_penalty`). Игрок не уходит в минус. Неоплаченное становится долгом `trade_debts` конкретному контрагенту (не счёту рынка): гасится из остатка денег в том же месяце и в следующих. Новый неоплаченный долг за этот месяц — такой же пропуск, как неоплаченные зарплаты или сырьё (`company_status.missed`), и доводит до банкротства по общим правилам.

НДС и налог на прибыль **не** считаются с оборота контракта (оборот рынка по-прежнему облагается). Иначе пришлось бы провести контракт через счёт `system:market` и сломать прямой перевод. Это осознанный предел первой версии, не дыра в журнале: журнал по-прежнему сходится в ноль.

## Расторжение

- Открытое предложение поставщик снимает бесплатно.
- Активный контракт может расторгнуть любая сторона. Пошлина = `penalty × qty` (штраф за месяц полной недопоставки) и платится контрагенту сразу. Нет денег — отказ `402`, контракт остаётся.
- Банкротство любой стороны снимает её активные контракты (`dissolved`). Из выручки ликвидации сначала платят прежние кредиторы (зарплаты, налоги, сырьё, обслуживание, банк), затем долги по контрактам; непогашенный долг банкрота списывается.
- Продажа здания контракт не отменяет. Пропавший выпуск и склад, который не вмещает запас, дают недопоставку и штраф. Так продажа склада учитывается без отдельной отмены.

## API

Авторизация: `Authorization: Bearer`. Деньги и количества с клиента не принимаются как факт — только поля ниже.

`GET /contracts` — открытые предложения (доска), мои контракты, мои долги, пределы цен.

`POST /contracts/offer`

```json
{"product":"honey","qty":40,"price":200,"term_months":6,"penalty":50,"request_id":"<uuid>"}
```

`POST /contracts/accept`

```json
{"offer_id":"<id>","request_id":"<uuid>"}
```

`POST /contracts/cancel`

```json
{"offer_id":"<id>","request_id":"<uuid>"}
```

или `{"contract_id":"<id>","request_id":"<uuid>"}`.

Ответы об ошибках: `invalid_request_id`, `invalid_product`, `invalid_qty`, `price_out_of_range` (с `min_price`/`max_price`), `invalid_term`, `invalid_penalty`, `too_many_offers`, `too_many_contracts`, `self_contract`, `npc_forbidden`, `not_found`, `not_open`, `not_owner`, `not_party`, `invalid_state`, `insufficient_funds`, `unauthorized`.

Успех создания — `201` и тело с `ok: true`. Повтор того же `request_id` — `200` и то же тело.

`GET /world` → `economy.contracts` добавляет пределы (старые поля не меняются).

## Клиент

Кнопка «Контракты» видна только на вкладке «Экономика». Панель скрыта, пока её не открыли: маршрутизатор касаний и так пропускает только `is_visible_in_tree()`, скрытая панель нажатий не получает. Принять можно только чужое открытое предложение, снять — своё.
