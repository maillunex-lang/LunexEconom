## Ветка и слияние
- Вся работа **только в ветке `GPTFirst`** (от свежего `main`). В `main` не пушить, PR не создавать и не сливать — слияние делает Claude по команде владельца.
- Параллельно Grok работает в `GrokFirst` над контрактами между игроками: **не трогай** его зону (серверные модули контрактов, таблицы контрактов, их панель клиента). Общие файлы (`game_server.py`, схемы БД) — только добавлением, минимальными хуками.

## Задача: рейтинг компаний и лента событий (read-only механики)
Цель — игроку видно, как идёт игра: кто лидирует и что с ним происходило. Это этап 0.4–0.5 (общий мир, соревновательность). **Деньги и состояние мира эта задача не меняет** — только читает.

1. **Рейтинг компаний** (`GET /leaderboard`, Bearer): топ-20 игроков и NPC-компаний по чистой стоимости (деньги + оценка зданий − долги банку), плюс строка самого игрока с местом. Параметры: `?by=networth|income|buildings`. Значения считаются из уже существующих данных (кошелёк, здания, кредиты, месячные отчёты `monthly_reports`); посмотри `economy.py`, `production.py`, `bank.py`, `npc.py`. NPC помечены `npc:true`. Имена игроков показывать как есть, без e-mail и служебных данных.
2. **Лента событий компании** (`GET /feed?after=N`, Bearer): последние события только этого игрока — постройка, продажа, месячный итог (прибыль/убыток), налоги, зарплата мэра, банкротство, кредит, выборы (кандидатура, итог). Источник — журнал проводок/отчёты/команды; новую таблицу заводи только если без неё нельзя (тогда с `CREATE TABLE IF NOT EXISTS` в обоих бэкендах).
3. **Клиент:** новые панели «Рейтинг» и «События» отдельными файлами (например `client/leaderboard_panel.gd`, `client/feed_panel.gd`), подключение в `world_screen.gd` одним добавочным вызовом и кнопкой. Не ломай HUD, hit-тест кнопок (`_hit_ui_button`: невидимое не реагирует на касания) и горизонтальную раскладку; проверь headless-запуском Godot.

## Правила (повтор главного)
- Новый серверный код — в **новом модуле** `server/stats.py` с `db` и плейсхолдером `ph`, работает на SQLite и PostgreSQL одинаково; хук в `game_server.py` — одна-две строки по образцу `ECONOMY_POST`/`/city`.
- SQLite-соединения закрывать (`sqlite_util`); никаких утечек.
- Тесты: `server/test_stats.py` (SQLite; PG-версия по образцу `test_postgres_*` с пропуском вне `lunex_ci`), добавь модуль в `server-check.yml` дописыванием в конец списка.
- Проверки: `cd server && python -W ignore -m unittest discover -p 'test_*.py'`, `cd ops && python -m unittest discover -p 'test_*.py'`; клиент — `godot --headless --path client --import` и запуск сцены без ошибок. Ничего не помечай «готово» без реально запущенных тестов.
- Секреты, боевая БД, чужие сервисы — не трогать. Периодически `git rebase origin/main`.
