# Администрирование игры (World Studio + игровой admin API)

Состав:
- **`admin_studio/`** — отдельный сервис (стандартная библиотека Python, своя SQLite): библиотека графики для игры (LivePatch), подписанные выпуски, черновики городов и раздел «Игра» (мониторинг и модерация).
- **`server/admin_api.py`** — административные адреса игрового сервера `/admin/*` (только чтение состояния + модерация + объявления). Экономику, деньги, здания и константы **не меняет**.
- **Клиент:** `client/livepatch.gd`, `client/patch_visuals.gd` (подгрузка картинок по подписанному манифесту; **не включена автоматически**), объявление для игроков в «Меню».

## Что умеет раздел «Игра»
| Возможность | Где |
|---|---|
| Мониторинг: игровой месяц, число аккаунтов/сессий/зданий/компаний, население, цены, кредиты, банкротства, бюджет города и системные счета, **проверка журнала** (несбалансированные проводки, сумма кошельков ≠ 0 → предупреждение) | `GET /admin/overview` |
| Игроки: список и поиск (без e-mail и паролей), карточка (баланс, здания, долги, кредит, последние 15 операций, жалобы, блокировка) | `/admin/players`, `/admin/player` |
| Блокировка и разблокировка (срок или бессрочно, причина, мгновенный выход из всех сессий) | `POST /admin/ban`, `/admin/unban` |
| Очередь жалоб (из `soc_reports`), решение «отклонить / приняты меры» с комментарием | `/admin/reports`, `POST /admin/report/resolve` |
| Объявление для всех игроков (до 200 символов, без `< >`), видно в «Меню» и в строке подсказки | `POST /admin/announce`, публичный `GET /announcement` |
| Начальная генерация городов: список городов (домов сейчас / по цели), план (ничего не пишет) и запуск, по умолчанию `dry_run` ([CITYGEN.md](CITYGEN.md)) | `GET /admin/cities`, `POST /admin/cities/seed` |
| Журнал действий администраторов (кто, что, когда, с какого адреса) | `GET /admin/audit`, таблица `adm_audit` |

Намеренно **нет**: правки денег, зданий, цен, констант экономики, времени. Это потребует отдельных идемпотентных серверных команд, ролей и подтверждения двумя людьми (см. «Что дальше»).

## Модель безопасности
1. **Игровой admin API недоступен из интернета.** Он принимает запрос только с `127.0.0.1` и **только если запрос не прошёл через обратный прокси** (nginx добавляет `X-Real-IP`; любой заголовок `X-Real-IP`, `X-Forwarded-*`, `Forwarded` → ответ `404`, даже с верным токеном). Публичный префикс `/lunexeconom/api/` поэтому админку не открывает. Без `LUNEX_GAME_ADMIN_TOKEN` длиной ≥ 32 символов API полностью выключен (`404`).
2. **Два разных секрета:** токен студии (`LUNEX_ADMIN_TOKEN`) и токен игрового API (`LUNEX_GAME_ADMIN_TOKEN`). Студия подставляет второй сама; браузер его не знает.
3. **Ограничение подбора:** 10 неверных токенов за 5 минут с одного адреса → `429` (студия — на адрес клиента, игровой API — глобально); сравнение токенов по хэшам байтов без исключений на не-ASCII.
4. **Таймаут чтения запроса 15 с** (защита от медленных соединений), лимит тела, строгий CSP, интерфейс только через `textContent`.
5. **Журнал** каждого изменения с исполнителем и адресом; отклонённые запросы не пишутся.
6. **Картинки:** PNG/WebP, до 8 МБ; **размеры читаются из заголовка** (≤ 2048×2048, ≤ 4 194 304 пикселей) на сервере студии и в клиенте до декодирования (защита от «бомб» вроде файла 249 КБ → 16000×16000 = 268 МБ).
7. **Подписанные выпуски (обязательное условие включения LivePatch):** клиент принимает манифест только с подписью RSA-SHA256, проверяемой открытым ключом из APK. Приватный ключ **никогда не попадает на сервер**: подпись делается на компьютере администратора (`admin_studio/sign_release.py`), сервер проверяет её тем же открытым ключом, прежде чем отдавать выпуск. При заданном `LUNEX_STUDIO_PUBLIC_KEY` сервер отдаёт клиентам **только подписанные** ревизии; откат создаёт новую ревизию и требует новой подписи.

## Переменные окружения
| Переменная | Где | Назначение |
|---|---|---|
| `LUNEX_GAME_ADMIN_TOKEN` | игровой сервер **и** студия | токен игрового admin API (≥ 32 символов, случайный) |
| `LUNEX_GAME_ADMIN_UPSTREAM` | студия | адрес игрового сервера, по умолчанию `http://127.0.0.1:18767` |
| `LUNEX_ADMIN_TOKEN` | студия | токен входа в студию (≥ 32 символов) |
| `LUNEX_ADMIN_BIND`, `LUNEX_ADMIN_PORT` | студия | по умолчанию `127.0.0.1:18991` — **не менять на публичный адрес** |
| `LUNEX_STUDIO_DATA` | студия | каталог данных студии (отдельная SQLite) |
| `LUNEX_STUDIO_PUBLIC_KEY` | студия | PEM открытого ключа проверки подписей выпусков |
| `LUNEX_WORLD_PREVIEW_UPSTREAM` | студия | источник для предпросмотра чанков (только чтение) |

Секреты не хранить в репозитории: задавать через `EnvironmentFile=` (права `600`, владелец root) в systemd.

## Запуск на VPS (когда решите включать)
1. Сгенерировать оба токена: `python3 -c "import secrets;print(secrets.token_urlsafe(48))"` (два разных).
2. **Игровой сервер:** добавить `LUNEX_GAME_ADMIN_TOKEN` в окружение `lunexeconom-game.service` и перезапустить службу. Таблицы `adm_*` создаются сами при старте.
3. **Студия** — отдельная служба, слушает только `127.0.0.1:18991`:
   ```ini
   [Service]
   User=lunex-studio
   WorkingDirectory=/opt/lunexeconom-studio
   EnvironmentFile=/etc/lunexeconom/studio.env
   ExecStart=/usr/bin/python3 server.py
   Restart=on-failure
   NoNewPrivileges=true
   ProtectSystem=strict
   ReadWritePaths=/var/lib/lunexeconom-studio
   ```
4. **Доступ к студии — только через SSH-туннель** (`ssh -L 18991:127.0.0.1:18991 сервер`, затем http://127.0.0.1:18991). Если нужен доступ по HTTPS: отдельный `server`-блок nginx на отдельном (непубличном) имени, TLS, `allow <ваш IP>; deny all;` и `auth_basic` как второй слой, `limit_req`, `proxy_set_header X-Real-IP $remote_addr;`. Не открывать студию на `/lunexeconom/api/`.
5. **Второй независимый слой для публичного nginx** (делается один раз, рядом с `location ^~ /lunexeconom/api/`): явно закрыть адреса админки на публичном домене. Этот блок должен стоять **выше** общего префикса:
   ```nginx
   location ^~ /lunexeconom/api/admin/ { return 404; }
   ```
   Даже без него игровой сервер не примет `/admin/*` от прокси (см. «Модель безопасности», п. 1); проверка снаружи: `curl -s -o /dev/null -w '%{http_code}' https://rikagro.ru/lunexeconom/api/admin/overview` должен дать `404`.
6. Автообновление игры (`ops/update_server.py`) обновляет только `server/*.py`; **студия обновляется вручную** (она не часть игрового сервера).

## Подпись выпусков (LivePatch)
Один раз, на своём компьютере:
```bash
openssl genrsa -out lunex-patch-private.pem 3072        # ПРИВАТНЫЙ КЛЮЧ: хранить офлайн, не в репозитории
openssl rsa -in lunex-patch-private.pem -pubout -out livepatch_public.pem
```
- `livepatch_public.pem` положить в `client/livepatch_public.pem` и пересобрать APK (**без этого файла клиент не примет ни одного патча**) и на сервер студии (`LUNEX_STUDIO_PUBLIC_KEY`).
- Опубликовать ревизию в студии, затем подписать:
  `LUNEX_ADMIN_TOKEN=… python3 sign_release.py --studio http://127.0.0.1:18991 --key lunex-patch-private.pem --revision N`
- Потеря ключа: выпустить новый APK с новым открытым ключом (старые установки патчей больше не примут). Компрометация: то же + сменить ключ немедленно.
- Автозапуск проверки обновлений в клиенте **не включён**: перед включением нужен тест на реальном устройстве, политика каналов и откат.
