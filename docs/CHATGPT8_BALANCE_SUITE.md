# Отчёт симулятора баланса

Инструмент: `tools/balance_sim.py`. Константы мёда, нефти и товаров не менялись:
каталог отдаёт прежние 200 / 1500 / 2000 ₽. Симулятор сам числа не правит.
Мир считается на временной SQLite вызовами `production.advance` (внутри — `step_month`);
часы подменены, реальная пауза не используется. NPC ходят через `npc.tick` (ошибка не глотается,
в отличие от `game_server.npc_tick`). Сумма всех проводок и сумма всех кошельков должны быть 0:
стартовый капитал, кредиты и оплата рынком — двойная запись, а не дырка в журнале.
Цена, налоги, население и проводки месяца — это закрытый месяц. Число зданий и деньги
сняты сразу после решений NPC и ботов на границе следующего месяца (так же сервер
вызывает npc_tick перед действием игрока), поэтому новое здание ещё не входило в выпуск.

Воспроизведение одного прогона:

```bash
cd tools && python balance_sim.py --months 72 --seed 20261114 --csv /tmp/npc72.csv
cd tools && python -m unittest discover -p 'test_*.py' -v
```

Пороги красных флагов: цена на границе 6 мес. подряд; качели потолок/ниже склада — от 4 раз;
население > 1600; шаг месяца > 500 мс; все 3 NPC без зданий после банкротства;
бюджет города < 0; 3 и больше банкротств за один месяц.
Границы цены: мёд 50–500, нефть 375–3750, товары 500–5000.

## Главное

Инварианты журнала (сумма проводок и кошельков равна 0, нет отрицательных запасов): **0 нарушений** в 8 сценариях.
Доля трат владельца по-прежнему 0,35 (`OWNER_SPEND_SHARE`); этот прогон её не менял. Подробности — `docs/OWNER_SPENDING.md`.
Мёд, нефть и товары задаются `server/goods_catalog.py` и совпадают с прежним рынком. Новые виды не входят в `economy.PRODUCTION` и `economy.MARKET`: месяц без агрозданий и скважин по-прежнему публикует ровно три цены. На нижней границе цены (`MIN_PRICE_K`) выручка нового производителя ниже содержания и зарплат, поэтому наращивать цепочку бесконечно убыточно (проверка — `server/test_goods_catalog.py`). NPC выбирают только старые виды.

## Длина месяца

Действия стоят на границе месяца (доля месяца = 0), поэтому экономика не должна
зависеть от `LUNEX_MONTH_SECONDS`. Отличается только подпись часов.

- **86400 с = 60 с** по всем целым метрикам.
- **86400 с = 600 с** по всем целым метрикам.

## Производительность шага

Здания вставлены напрямую в `buildings` / `building_ops` (без поиска дороги),
примерно по 10 на компанию, у каждой стартовый капитал. Замеряется один `production.advance`
ровно на один игровой месяц. Это стоимость месячного расчёта, не стоимость стройки.

## Что с этим делать

Ниже только наблюдения этого прогона и предложения. Симулятор сам константы не менял;
решение о правках — за владельцем. Подробности флагов — в сценариях выше (seed, месяц, метрика).

- **slow_step.** Месячный шаг дороже бюджета. Смотреть число компаний, а не только зданий: расчёт идёт по компании и пишет проводку. На боевом месяце (сутки) это терпимо, на тестовых 60 с — уже нет.

Отдельно, даже если флага нет: казна `system:treasury` отрицательная ровно на выданный стартовый капитал
(и награды мэра, если они были). Это не ошибка журнала. Ошибка — ненулевая сумма кошельков.

## Не проверялось

- PostgreSQL (симулятор сознательно только SQLite; боевую базу не открывает).
- Клиент Godot и HTTP (каталог и месторождения описаны в `docs/INDUSTRIES.md`).
- Сценарии с контрактами есть (`contracts_24`); это не проверка всех ограничений контракта.
- Межгородская логистика новых товаров (элеватор — общая складская ёмкость компании, не отдельный силос).
