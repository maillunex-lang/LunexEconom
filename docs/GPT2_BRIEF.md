Сначала прочитай [ROUND3.md](ROUND3.md) (общие правила — обязательны), затем [GROK_BRIEF.md](GROK_BRIEF.md) (контекст), [ROADMAP.md](ROADMAP.md), [PROGRESS.md](PROGRESS.md).
Работаешь **только в ветке `ChatGPTTwo`**. Твоя зона — эксплуатация, вход и онбординг (`ops/*`, `web/*`, `server/auth.py`, workflows, новые файлы). Таблицы БД — с префиксом `ops_`.

## Задачи (по порядку)

### 1. Версия сервера в `/health` (малое, сделай первым)
Сейчас `/health` отдаёт `"commit": null` — по нему нельзя понять, какой код развёрнут. Автообновление (`ops/update_server.py`) пишет SHA в `/var/lib/lunexeconom-server-update/deployed-sha`.
Сделай так, чтобы `health_details()` в `server/game_server.py` читал этот файл (путь из переменной `LUNEX_DEPLOYED_SHA_FILE`, по умолчанию как выше; при отсутствии файла — `null`, без ошибки и без раскрытия путей) и отдавал `commit` (первые 12 символов). Тест на оба значения. Совместимо с PostgreSQL-вариантом `postgres_world`.

### 2. Версионные миграции PostgreSQL (BE-004)
Сейчас схема создаётся `CREATE TABLE IF NOT EXISTS` при старте, версий и отката нет. Сделай:
- таблица `schema_migrations(version, name, applied_at, checksum)`; нумерованные миграции в `server/migrations/NNN_name.sql` (или `.py`), применяются по порядку, повторный запуск ничего не делает, изменённая применённая миграция (checksum) — ошибка;
- **baseline `001`** = точное текущее состояние схемы (все таблицы из `postgres_db.SCHEMA`, существующие на `main`), чтобы живая боевая база **распознавалась как уже на версии 1 без изменений данных**; запуск на пустой базе даёт ту же схему;
- модули других веток создают свои таблицы по-старому (`CREATE TABLE IF NOT EXISTS`) — раннер миграций их **не удаляет и не ломает**;
- команда `python server/migrate.py status|up` и вызов `up` при старте сервера **только при `LUNEX_AUTO_MIGRATE=1`** (по умолчанию выключено); откат «вниз» не нужен, но у каждой миграции — описание обратимости в комментарии;
- тесты на одноразовой базе `lunex_ci`: чистая база → baseline; база «как боевая» (создана старым способом) → распознана; повторный запуск; изменённый checksum;
- документ `docs/MIGRATIONS.md` (как добавлять миграцию, как проверить на копии боевой базы через `ops/postgres_restore_drill.py`).
**Не меняй** существующие `CREATE TABLE` в `postgres_db.py` и не запускай ничего на боевой базе.

### 3. Доставка писем (коды подтверждения и восстановления)
Сейчас письма не отправляются (нет провайдера). Реализуй отправку через SMTP, настраиваемую **только переменными окружения** (`LUNEX_SMTP_HOST/PORT/USER/PASSWORD/FROM`, TLS по умолчанию); без настроек — прежнее поведение (коды не отправляются, без ошибок). Ограничения: лимит писем на адрес и на IP, текст по шаблону без пользовательского HTML, повторная отправка не раньше чем через 60 с, ошибка SMTP не ломает регистрацию и не раскрывает наличие аккаунта. Тест на локальном фиктивном SMTP-сервере (стандартная библиотека), без внешней сети. Документ `docs/EMAIL.md`: какие переменные задать на VPS (значения не писать). **Секреты в репозиторий не класть.**

### 4. Обучение новичка (клиент)
Новый файл `client/tutorial.gd` (+ смоук `client/tests/tutorial_smoke.gd`): ненавязчивые подсказки первого запуска — «построй ферму», «открой Экономику», «посмотри Город», «загляни в Контракты» — с кнопкой «Пропустить»; состояние хранить локально (`user://`, обёрнуто в проверки ошибок), для нового аккаунта показывать один раз; шаги засчитываются по реальным событиям (построил — шаг выполнен), без блокировки игры. Подключение в `world_screen.gd` одним добавочным вызовом. Окна и касания — по правилам [ROUND3.md](ROUND3.md) п. 5.

### 5. Проверка внешних маршрутов API
Скрипт `ops/check_api_routes.py` (+ тест с подменой сети): для списка адресов из `server/game_server.py` (GET и POST) запрашивает публичный базовый URL (параметр, по умолчанию `https://rikagro.ru/lunexeconom/api`) и проверяет, что **ни один не отвечает HTML-404 от nginx** (допустимо: 200, 401/405/404 с JSON). Нужна из-за инцидента 14.11.2026 ([NGINX_API_ROUTES.md](NGINX_API_ROUTES.md)). Добавь запуск вручную (`workflow_dispatch`) в **новом** workflow `.github/workflows/api-routes-check.yml`; в `docs/NGINX_API_ROUTES.md` допиши, как запускать.

## Критерии приёмки
Все 5 пунктов с тестами; `/health` показывает коммит; миграции доказаны на `lunex_ci` (чистая и «как боевая»); письма проверены на фиктивном SMTP; обучение проходит смоук; существующие тесты (SQLite, PostgreSQL, ops, Godot) зелёные. В отчёте отдельно: что **не** проверено (например, реальная отправка почты, реальное устройство).
