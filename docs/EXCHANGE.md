# Биржа по городам (gpt5)

## API

### POST /soc/exchange/order

Совместим с прежним endpoint. Авторизация игрока обязательна. JSON:

```json
{"product":"honey","side":"buy","qty":4,"price":150,"city_id":"ufa","allow_intercity":true,"request_id":"UUID"}
```

- `city_id`: необязательный ID города из `regions.region_ids()`. Если не передан, выбирается `regions.home_region(db,ph,owner)`. Для продавца иной город допустим только при наличии собственного действующего предприятия в городе. Для покупателя это город доставки.
- `allow_intercity`: необязательный bool, **по умолчанию false**. Без разрешения покупателей межгородские предложения не сопоставляются, и старые клиенты не платят за перевозку неожиданно.
- Для межгорода покупатель заранее резервирует цену заявки плюс максимум возможной перевозки для всех известных городов на единицу, затем излишек возвращается. Цена сделки равна цене заявки, стоящей в стакане. Стоимость перевозки: `regions.unit_cost(product, seller_city, buyer_city) × qty` в рублях, целочисленно, за счёт покупателя. Плата в размере 1% стоимости товара взимается с продавца по прежним правилам.
- Выплаты двойной записью: из escrow списываются стоимость товаров и перевозка; продавцу поступает стоимость товаров за вычетом биржевой комиссии; городу поступают комиссия и перевозка. Таким образом сумма всех проводок остаётся нулевой, дополнительная эмиссия отсутствует. Товары переводятся со склада продавца в инвентарь покупателя в момент сделки. Время физической перевозки и складская геопривязка товарных остатков пока **не реализованы**. Нельзя обещать задержку доставки.
- JSON ответа сохраняет `order`, `fills`, `balance`, `stock`, `month`. Для межгородской записи `fills[]` дополнительно содержит `transport_cost`, `seller_city`, `buyer_city`. Для сделок внутри города прежний формат `fills[]` сохраняется.

### GET /soc/exchange/book?product=honey[&city_id=ufa]

Отдаёт прежние сводные `bids`, `asks`, `products`, а также `cities[]` со стаканами по городам, `viewer_city_id`, `max_transport_unit`, `city_id`. В `cities[].transport_unit_cost_to_viewer` цена доставки единицы товара из данного города в город покупателя. При `city_id` отображается только выбранный стакан. Для просмотра потребуется существующая авторизация.

### GET /soc/exchange/mine, POST /soc/exchange/cancel

В списке заявок дополнительно `city_id`; отмена освобождает неиспользованный денежный резерв покупателя или остаток товара продавца.

## Схема, совместимость и эксплуатация

`server/exchange.py` в разрешённой области добавляет поля к существующим таблицам при первом обращении к заявкам: `soc_orders.city TEXT DEFAULT 'ufa'`, `soc_orders.transport_reserve_unit BIGINT DEFAULT 0`, `soc_fills.seller_city`, `buyer_city`, `transport_cost`. Старые заявки остаются в Уфе и не имеют резерва на межгородскую перевозку, следовательно их нельзя исполнять с неоплаченным фрахтом. Изменений `server/social.py` и прочих файлов, которыми занимается Grok, нет.

**Ограничение:** DDL выполняется при обработке запроса; для PostgreSQL это может вызывать блокировки при первом обращении. После согласования со стороны Grok лучше вынести расширение схемы в обычную миграцию и индекс по `(product, city, status)` для больших книг, **не добавляя это в чужие файлы из ветки gpt5**. Перед выкаткой на VPS требуется снимок базы и отдельное разрешение владельца на изменение схемы.
