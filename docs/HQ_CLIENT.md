# EX-13 / EX-11. Android-клиент штаб-квартиры (ChatGPT10)

Дата: 15.11.2026. Исполнитель ChatGPT1, ветка `ChatGPT10` от `origin/main` (`faac236` на старте).

## Архитектура и навигация

- `client/hq.tscn`: один `Control`, без `Node3D`; `client/hq/hq_screen.gd`: Forest Glass, шапка, навигация, обзор, списки и оповещения; `client/hq/hq_chart.gd`: простой статический `_draw`-график, повторно рисует только при новых данных/изменении окна; оригинальный (не заимствованный) фон `client/hq/art/headquarters.svg` (собственный SVG, менее 4 КБ). `client/hq/hq_api.gd`: режим образца и авторизованный GET.
- В `main.gd` после успешного логина и подтверждённого `/auth/rotate` вызывается `_enter_hq()`. На карте `world_screen.gd` добавлены кнопка «В штаб-квартиру» и короткий хук `_restore_hq_focus()`. Если переход из карточки предприятия, передаются координаты и `world.focus_cell(Vector2i(x,y))`, затем `world.select_cell(...)`. Старая `world.tscn`, все прежние панели и меню строительства сохранены.
- Для освобождения 3D используется `SceneTree.change_scene_to_file`, а не скрытие `Node3D`. При переходе в штаб предыдущая сцена мира выгружается, поэтому мировые `_process`, таймеры `world_sync` и 3D-сцена отсутствуют. Повторное открытие мира требует создания мешей/загрузки чанков, но гарантия отсутствия рендеринга 3D в штабе важнее постоянного хранения огромной сцены.
- Только горизонтальный экран Android, `DisplayServer.get_display_safe_area()` с запасом, прокрутка в трёх колонках, цель касания кнопок по высоте минимум 48 виртуальных px; при ширине менее 1020 px правая панель скрывается, данные сохраняются в сводке.
- Нет циклических анимаций/таймеров обновления кадров; данные при изменении перерисовывают карточки, график вызывает `queue_redraw` только после изменения истории.

## API и режим заглушки

- `GET /hq` максимум раз в 15 секунд при видимой сцене; если запрос ещё в работе, второй не стартует. В фоне (`NOTIFICATION_APPLICATION_PAUSED`) таймер останавливается и активный запрос отменяется; при возвращении запрос выполняется не раньше разрешённого интервала.
- Запросы снабжены `Authorization: Bearer` из `GameSession`; `GET /hq` не должен подменять серверную экономику локальными расчётами. Неизвестные поля JSON игнорируются, необязательные поля читаются со значениями по умолчанию.
- Настройки → «Данные: сервер / демо JSON» сохраняется локально в `user://hq.cfg`. Образец `client/tests/hq_sample.json` повторяет `docs/HQ_SCREEN.md`. По умолчанию активен сервер, чтобы не показывать игроку фальшивый баланс без предупреждения.
- Уже доступные окна первой очереди читают действующие `GET /city`, `GET /market`, `GET /contracts`, `GET /wallet`, `GET /soc/exchange/book?product=honey`; /hq показывает рейтинг компании, город, задолженность и сводки. Предприятие «Управление» читает `GET /enterprise?id=...` с корректной деградацией на 404. Команд на изменение цен/счёта эта версия не посылает.
- Будущие окна (земля, недвижимость, население, банки, логистика, строительные действия) показывают «Скоро» до завершения соответствующих серверных API. Подключение следует `docs/HQ_SCREEN.md` и будущему `docs/HQ_API.md`; эти маршруты клиент не выдумывает.

## Тестирование

```sh
GODOT=/opt/game-tools/godot/4.7.2-stable/Godot_v4.7.2-stable_linux.x86_64
$GODOT --headless --path client --script res://tests/hq_smoke.gd
$GODOT --headless --path client --script res://tests/hq_layout_smoke.gd
$GODOT --headless --path client --script res://tests/hq_navigation_smoke.gd
$GODOT --headless --path client --script res://tests/hq_perf_smoke.gd
xvfb-run -a $GODOT --path client --rendering-driver opengl3 --script res://tests/hq_screenshot.gd -- <папка>
```

- `hq_smoke.gd`: JSON, заголовок, финансовый график, предприятия и оповещения, запрет Node3D, отсутствие опросов при скрытой сцене, маршруты.
- `hq_layout_smoke.gd`: размеры 846×388, 1280×720, 2340×1080, центральная область, доступность касания.
- `hq_navigation_smoke.gd`: настоящий переход из штаба к карте и фокус на (40, 12), выбор клетки, возврат и отсутствие 3D после возврата.
- `hq_perf_smoke.gd`: 90 кадров каждой сцены, `Performance.TIME_PROCESS`, среднее/пик, время создания сцены, лимит FPS.
- CI: смоуки добавлены в `.github/workflows/client-check.yml`, ветка `ChatGPT10` включена в push-триггер. Android APK собирается существующим `android-build.yml` на ветке `ChatGPT10` (публикация релиза остаётся только из `main`); локальный debug APK успешно экспортирован Godot 4.7.2 и проверен apksigner; содержимое Android export preset не меняется.

Повторный прогон того же теста дал: штаб 22,799 мс среднего (пик 68,332 мс), карта 16,581 мс (пик 212,534 мс); порядок показателей поменялся. Это демонстрирует, что сравнивать потребление по одному загруженному VPS некорректно.

Headless-замер относится к загруженному VPS, не является измерением энергии Android: на настоящем устройстве нужны Battery Historian/Android Profiler, GPU frame time, энергопотребление и термопрофиль при 5–10 мин в каждой сцене. Сравнение допускает разброс из-за других процессов на VPS. Освобождение карты избрано по однозначному отсутствию 3D-процессов во время работы штаба, а не по измеренной батарее.

## Не сделано / ограничения

- Серверная часть ChatGPT11 уже слита в main: `GET /hq`, `GET /enterprise` доступны по контракту `docs/HQ_API.md`. В реальном режиме запросы авторизованы; тестовый JSON используется только при ручном выборе демо-режима. Изменение настроек предприятия в этом клиентском задании не подключено.
- Данные действующих маршрутов города, рынка, биржи, контрактов и кошелька представлены читаемыми сводками, а не полными формами действий; расширение без дублирования старых UI после согласования контрактов.
- График использует необязательный `history` сервера; если истории в /hq нет, график пуст, без искусственно выдуманного ряда.
- Скриншоты Xvfb не подтверждают поведение сенсорного экрана, реальную safe area с вырезом и энергоэффективность устройства.
- Локальный debug APK экспортирован и проверен `apksigner`; CI после push ещё не подтверждён. В исходном проекте нет значка приложения (предупреждение экспортера), требуется отдельный дизайн.
