# Журнал Grok2 (ветка Grok2First)

## 2026-11-14 — симулятор баланса и стресс-тест экономики

Игровой код не менялся (`server/*.py`, `client/*`, `ops/*`, `web/*`). Новые файлы только в `tools/` и отчёты. В `.github/workflows/server-check.yml` добавлена одна строка: прогон `tools/test_*.py`.

### Что сделано
- `tools/balance_sim.py` — прогон серверной экономики на временной SQLite без HTTP. Месяцы двигаются подменой `game_server.time.time` и вызовом `production.advance` (внутри `step_month`). NPC — через `npc.tick` (ошибка не глотается, в отличие от `game_server.npc_tick`). Боты: `rotate` (строит по кругу), `hoard` (одна ферма и копит), `loan` (берёт весь доступный кредит и строит самое дорогое), `idle` (только стартовый капитал).
- Метрики месяца в CSV: цены, предложение и спрос, население и безработица, здания, деньги игроков / NPC / казны / города / рынка / жителей / банка, налоги, банкротства, сумма проводок и кошельков.
- Инварианты: сумма проводок = 0, сумма кошельков = 0, нет кривых проводок, нет отрицательных `player:*` (включая NPC и город), нет отрицательных запасов.
- Красные флаги: цена на границе много месяцев подряд, качели «потолок / ниже порога склада», население 0 / на минимуме / раздулось, все NPC после банкротства без зданий, бюджет города < 0, шаг дольше бюджета, незамкнутый денежный круг, пачка банкротств за один месяц.
- Замер шага на 50 / 200 / 1000 зданиях (вставка в таблицы, без поиска дороги).
- `tools/test_balance_sim.py` — 24 месяца только NPC (инварианты + тот же seed → тот же ряд), боты, длина месяца 60/600/86400, пропорция половины месяца, детектор флагов, отказ открывать PostgreSQL не на `lunex_ci`.
- `docs/BALANCE_REPORT.md` и ряды `tools/samples/*.csv` — фактический прогон, не придуманные цифры.

### Риски
- Фильтр `paths` в `server-check.yml` не включает `tools/**` (менять workflow шире одной строки со списком тестов нельзя). Этот коммит трогает сам workflow, поэтому проверка на нём запустится. Следующий коммит только в `tools/` workflow не стартует, пока не изменится `server/` или сам yaml.
- Цифры отчёта привязаны к текущему `economy.py`. После rebase на `main`, если баланс там изменится, ряды в `tools/samples/` устареют; юнит-тесты проверяют инварианты и детерминизм, а не конкретные цены 72-го месяца.
- `game_server.npc_tick` по-прежнему глотает ошибки NPC. Симулятор вызывает `npc.tick` напрямую, чтобы такие ошибки были видны.

### Найденные проблемы (игровой код не менялся)
Подробности, seed и месяц — в `docs/BALANCE_REPORT.md`.

1. Качели складов. Порог `HOLD_BELOW` прячет 100 % выпуска у всех сразу: нефть с месяца 64 (seed 20261114, только NPC) чередует предложение 0 / цену 3750 ₽ и обвал ниже 1350 ₽. Мёд при лишних фермах — с месяца 37.
2. Незамкнутый круг. За 72 месяца только NPC `system:market` = −34 357 751 ₽, `system:residents` = +10 265 959 ₽. Сумма кошельков 0: это не дырка журнала, а бездонный покупатель и нетратящие жители.
3. Кредитные боты умирают пачкой (seed 3, месяц 6, списано по 278 835 ₽). К месяцу 59 кредитов нет, `system:bank` всё ещё −688 689 ₽. NPC не банкротятся. Бюджет города в минус не уходил, население в ноль не падало.
4. Шаг месяца дешёвый: 1000 зданий / 100 компаний ≈ 17 мс. Бюджет 500 мс не превышен.
