# Предложение 07. Население и спрос

**Цель:** смоделировать жителей городов, их доходы, расходы и спрос на товары так, чтобы розница из модуля 06 получала реалистичный суточный спрос, зависящий от населения, доходов, цен и качества предложения.

## Сущности и данные

- Город: население `pop` (целое), средний доход `income_index` относительно Уфы, доля занятых, качество жилья и услуг.
- Район города: население района, тип (центр / жилой / окраина), трафик.
- Слой дохода: 4 слоя (низкий, средний, высокий, премиум). Доли: 0.35 / 0.40 / 0.20 / 0.05 (balance: draft).
- Потребительская корзина: набор категорий товаров (из `docs/content/products.ru.md` и каталога): еда (хлеб, молоко, мясо, овощи, мёд), одежда, топливо, электроника, стройматериалы и т.д. Для каждой категории — базовая доля расходов и эластичность.
- Домохозяйство (агрегат): не хранится поштучно, считается по району и слою.
- Миграция: поток людей между городами по разнице привлекательности (работа, жильё, услуги).

Данные: `city_population` (город, день, pop, layers), `district_demand` (район, товар, день, спрос), `migration_flows`.

## Правила и формулы

Суточный спрос на товар `g` в районе:

```
demand_g = pop_district * base_per_capita_g * income_factor * price_sensitivity * rating_factor * ad_factor
```

где:
- `base_per_capita_g` из каталога (на 1000 жителей, приводим к 1);
- `income_factor` = 0.6 + 0.4 * income_index слоя (balance: draft);
- `price_sensitivity` = clamp(1 - elasticity * (price / ref_price - 1), 0.3, 1.5);
- `rating_factor` = 0.7 + 0.3 * (avg_R / 100) (связь с рейтингом из 06);
- `ad_factor` = 1 + 0.1 * log(1 + ad_budget) (M3, в M2 = 1).

Пример (balance: draft): район 10 000 жителей, хлеб `base_per_capita` = 0.8 кг/день на человека, цена = эталон, R = 70 → demand ≈ 8000 кг.

Рост населения:

```
delta_pop = pop * (0.001 * housing_quality + 0.0005 * jobs_available - 0.0003 * unemployment)
```

в день (balance: draft). Убыль при плохом жилье и безработице.

Занятость: число рабочих мест = сумма `jobs` по предприятиям города. Зарплата = базовая_Уфа * city_wage_index * skill_factor (из 10).

Миграция: 0.5 % населения в день рассматривает переезд. Вероятность в город B = attractiveness_B / sum. Attractiveness = jobs_ratio * housing_ratio * service_ratio.

## Что считается в суточном тике и что в месячном

**Суточный тик** (после `retail` или перед ним, порядок согласовать):
1. Обновить население по росту/убыли.
2. Посчитать спрос по районам и товарам.
3. Передать спрос в розницу (модуль 06 использует его вместо упрощённой модели M1).
4. Обновить занятость и средние зарплаты (для отображения).

**Месячный шаг:**
- Сводка доходов и расходов населения.
- Пересчёт индексов привлекательности городов.
- Миграция (можно и суточно, но агрегировать месячно).

## Проводки ledger

Население не имеет счетов. Выручка магазинов идёт от счёта `system:market` или `city:<id>:households` на компанию (как в 06). Зарплаты — отдельными проводками в месячном шаге из `company:<id>` на `system:labor` (или напрямую на «население», но баланс 0).

Пример: продажа хлеба на 10 000 ₽ → проводка `{company: +10000, system:market: -10000}`.

## API

- `GET /cities/{id}/population` — pop, layers, employment.
- `GET /cities/{id}/demand?day` — спрос по товарам.
- `GET /world/migration` — потоки.
- `POST /admin/population/adjust` (только админ) — для тестов.

## Что показывает клиент

В штабе и на карте города: население, средний доход, занятость, «спрос на хлеб сегодня», подсказки «почему продажи низкие» (дорого / низкий рейтинг / мало населения).

## Приёмка

- Спрос в районе с 10 000 жителей на хлеб положительный и зависит от цены (снижение цены повышает спрос в пределах эластичности).
- Рост жилья и рабочих мест увеличивает население за 30 дней.
- Два магазина в одном районе делят спрос пропорционально привлекательности (как в 06).
- Все деньги через ledger, сумма 0.
- В M1 упрощённая модель заменяется этой без поломки существующей розницы.

## Открытые вопросы к директору

1. Сколько слоёв дохода — 3 или 4? Рекомендация: 4, проще балансировать премиум.
2. Считать спрос по районам или по городу целиком в первой версии? Рекомендация: по районам, как заложено в 06.
3. Миграция суточная или месячная? Рекомендация: суточная с малым коэффициентом.
4. Нужен ли отдельный счёт `city:households` или достаточно `system:market`? Рекомендация: `system:market` для простоты.
5. Как сильно реклама влияет в M2 (до модуля медиа)? Рекомендация: ad_factor = 1 до M3.
6. Базовый рост населения 0.1 % в день — нормально или слишком быстро? Рекомендация: 0.05 % в день.
7. Нужно ли моделировать безработицу как отдельный параметр, влияющий на спрос? Рекомендация: да, снижает income_factor.
8. Экспорт/импорт населения между регионами? Рекомендация: нет в M2, только внутри 20 городов.

## Дополнительные детали и примеры

### Потребительские корзины по слоям (balance: draft)

| Слой | Доля населения | Доля расходов на еду | На одежду | На топливо | На электронику |
|------|----------------|----------------------|-----------|------------|----------------|
| Низкий | 35 % | 55 % | 10 % | 15 % | 2 % |
| Средний | 40 % | 40 % | 15 % | 12 % | 8 % |
| Высокий | 20 % | 25 % | 20 % | 10 % | 15 % |
| Премиум | 5 % | 15 % | 25 % | 8 % | 25 % |

Пример расчёта спроса на хлеб в районе 5000 человек (средний слой доминирует):

- base_per_capita = 0.7 кг
- income_factor среднего = 1.0
- price = 1.1 * эталон → price_sensitivity ≈ 0.85
- avg_R = 60 → rating_factor = 0.88
- demand ≈ 5000 * 0.7 * 1.0 * 0.85 * 0.88 ≈ 2618 кг

### Связь с розницей (модуль 06)

Модуль 07 отдаёт `demand_g` по районам. Розница делит его между ячейками по формуле `A^s`. Если суммарный спрос района меньше предложения — остатки на полках. Если больше — нехватка, оповещение.

### Рост и убыль

При housing_quality = 80 (из 08), jobs_available / pop = 0.6, unemployment = 0.1:

delta_pop = pop * (0.001*0.8 + 0.0005*0.6 - 0.0003*0.1) = pop * 0.00107

За 30 дней ≈ +3.2 % (balance: draft, можно снизить коэффициенты).

### Миграция

Город A attractiveness = 1.2, город B = 0.8. Из 1000 рассматривающих переезд: 600 в A, 400 в B.

### Занятость и зарплаты

Рабочие места = sum(jobs по работающим предприятиям). Если мест меньше населения трудоспособного возраста (70 % pop) — безработица. Зарплата = 74 000 реальных ₽ / 50 * city_index ≈ 1480 игровых ₽ в месяц в Уфе (balance: draft).

### Граничные случаи

- Население района 0 → спрос 0.
- Цена в 3 раза выше эталона → price_sensitivity = 0.3 (минимум).
- Нет магазинов в районе → спрос не удовлетворяется, миграция растёт.

### Данные для тестов

Стартовое население Уфы ≈ 1 150 000 (реальное), других городов пропорционально. Индексы из 02.
