# Предложение 07. Население и спрос (готово к постановке)

**Цель:** смоделировать жителей городов по районам и четырём слоям дохода, считать суточный спрос по товарам каталога и передавать его рознице (06). Все расчёты по INTEGER_MATH.md. Никаких float. Счета не уходят в минус.

Утверждено владельцем (DECISIONS_APPROVED.md):
- D-01: четыре слоя дохода
- D-02: спрос считается по районам
- D-04: платежи покупателей со счёта system:market
- D-18: цена на полке включает НДС 1000 bp

## Сущности и данные

### Район города
- `district_id`: целое, уникальное в городе
- `type`: центр / жилой / промзона / окраина / рынок / вокзал (из city_districts.ru.md)
- `pop_‰`: доля населения города в промилле (1000 = 100 %)
- `traffic`: 0–100, целое
- `cells`: список клеток карты, привязанных к району

Привязка районов к клеткам детерминированная:
1. Центр города — клетка с минимальным расстоянием до ратуши из world.md.
2. Жилой — кольцо вокруг центра до радиуса city_radius - 4.
3. Промзона и окраина — по зонам из world.md.
4. Рынок и вокзал — фиксированные точки из city_districts*.ru.md.

Население района = (pop_city * pop_‰) // 1000.

### Слои дохода (D-01)
Четыре слоя, доли в промилле (balance: draft):
- Низкий: 350 ‰
- Средний: 400 ‰
- Высокий: 200 ‰
- Премиум: 50 ‰

Корзины потребления (промилле от дохода слоя, реальные категории из products.json):

| Слой | Еда (bread, flour) | Одежда | Топливо | Электроника |
|------|----------------------|--------|---------|-------------|
| Низкий | 550 | 100 | 150 | 20 |
| Средний | 400 | 150 | 120 | 80 |
| Высокий | 250 | 200 | 100 | 150 |
| Премиум | 150 | 250 | 80 | 250 |

Единицы спроса = unit из каталога (piece для хлеба, kg для муки).

## Правила и формулы (целочисленные)

Суточный спрос товара `g` в районе для слоя `l`:

```
base = (pop_district * base_per_capita_g * layer_share_‰) // 1000
income_factor_‰ = 600 + (400 * income_index_layer) // 1000
price_delta_bp = ((price - ref_price) * 10000) // ref_price
price_sens_‰ = clamp(1000 - elasticity * price_delta_bp // 100, 300, 1500)
rating_factor_‰ = 700 + (300 * avg_R) // 100
ad_factor_‰ = 1000   // до M3 (D-05)
demand_layer = (base * income_factor_‰ * price_sens_‰ * rating_factor_‰ * ad_factor_‰) // 1000000000000   // четыре множителя в промилле, 1000^4
demand_g = sum(demand_layer по 4 слоям)
```

Порядок умножений слева направо, промежуточные результаты не превышают bigint. ad_factor только умножение // 1000.

**Пример 1. Хлеб в центральном районе Уфы**
- pop_city = 1150000, pop_‰ центра = 180, pop_district = (1150000 * 180) // 1000 = 207000
- base_per_capita = 2, средний слой 400 ‰
- base = (207000 * 2 * 400) // 1000 = 165600 штук в сутки на слой при эталонной цене и рейтинге
- income_factor_‰ = 1000, price_sens_‰ = 1000, rating_factor_‰ = 910, ad_factor_‰ = 1000
- demand_layer = (165600 * 1000 * 1000 * 910 * 1000) // 1000000000000 = 150696 штук в сутки (165600 * 910 // 1000)
- Промежуточное произведение 165600 * 10^12 * 0.91 порядка 1.5 * 10^17 помещается в bigint (предел около 9.2 * 10^18); при росте base в 50 раз и более считать по шагам с делением после каждых двух множителей.
- Сумма по четырём слоям зависит от долей слоёв и индексов дохода; пример на один средний слой, итог по району получается сложением четырёх таких величин (проверка: если доли слоёв в сумме дают 1000 ‰, а факторы равны, итог равен 150696 * 1000 // 400 = 376740 штук в сутки).

**Пример 2. Цена +10 %**
price_delta_bp = 1000, price_sens_‰ = 990. Спрос снижается на ~1 %.

Рост населения района:
```
growth_bp = housing_quality + (jobs_ratio_‰ // 100) - (unemp_‰ // 50)
delta_pop = (pop_district * growth_bp) // 1000000
```

## Связь с розницей (06)

Модуль 07 отдаёт `demand_g` по районам. Розница делит спрос района между магазинами района пропорционально рейтингу A^s (как в 06). Платежи идут со счёта `system:market` (D-04). Цена на полке включает НДС 1000 bp (D-18).

## Что считается в тиках

**Суточный:**
1. Обновить pop районов по росту
2. Посчитать спрос по районам и товарам
3. Передать в 06

**Месячный:**
- Миграция между городами
- Пересчёт привлекательности

## API

- GET /cities/{id}/districts — список районов, pop, type, traffic
- GET /cities/{id}/demand?day&district — спрос по товарам
- GET /cities/{id}/population — общее и по слоям

## Что показывает клиент

На карте: границы районов, население, спрос на основные товары. В штабе: слои дохода, занятость.
