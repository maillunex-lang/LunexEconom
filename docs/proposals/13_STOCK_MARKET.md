# Предложение 13. Фондовый рынок (полная спецификация)

**Цель:** IPO, стакан, дивиденды из прибыли и упрощённое поглощение. Капитализация — витрина, не источник денег. Это не товарная биржа 05 и не цена полки 06: котировка не меняет спрос и розницу. Город (02) акций не выпускает. Деньги только через журнал 01. База дивиденда — прибыль после налога 09 и городского налога 14. Контрольный пакет стыкуется с холдингом 10 (потолок 5 компаний). Веха M4, директором не утверждено.

Все расчёты по `docs/proposals/INTEGER_MATH.md`. Никаких float. Счета компании и игрока не уходят в минус. `system:treasury` и `system:escrow` — как в platform.md.

## Сущности и данные

### share_issues
- company_id: целое, одно IPO на компанию
- total_shares: целое >= 1
- par_price: целые ₽
- status: open / listed / withdrawn
- listed_day: day_index

### share_holdings
- company_id, holder_account (`player:<имя>` или `company:<id>`)
- shares >= 0, qty_locked >= 0 (акции в заявках на продажу)
- Уникально (company_id, holder_account). Свои акции компания не голосует.

### share_orders
- id, request_id (уникальный)
- company_id, owner_account, side: buy / sell
- limit_price >= 1, qty, qty_left
- created_seq: монотонный номер внутри дня
- status: open / filled / cancelled, day_index

### share_trades
- buy_order_id, sell_order_id, price, qty, fee, day_index
- request_id: `trade:<buy_id>:<sell_id>:<fill_seq>`

### dividend_runs
- company_id, month_index, profit_after_tax, payout_‰, per_share, paid_total, remainder_kept
- request_id: `dividend:<company_id>:<month_index>`

Капитализация не хранится: считается из последней сделки.

## Правила и формулы

`fee_bp = 10` (balance: draft, D-43). Полоса `800–1200 ‰` от last (balance: draft). `payout_‰` 0–1000, старт 0 (D-62). Контроль с `5000 bp`. Новых заявок не больше 100 на счёт в день (balance: draft, D-42).

### IPO
Покупатели платят фиксированную par_price. Непроданное сжигается.
```
gross = sold * par_price
fee = (gross * fee_bp) // 10000
net = gross - fee
```
**Пример 1.** 1000 акций по 1000 ₽, спрос 1000. gross = 1 000 000. fee = (1000000 * 10) // 10000 = 1000. net = 999 000. Инвесторы −1 000 000, компания +999 000, treasury +1000.
**Пример 2.** Спрос 600. gross = 600 000, fee = 600, net = 599 400, total_shares = 600. Арифметика проверена дважды.

### Сопоставление
Покупка: цена убывает, затем created_seq. Продажа: цена возрастает, затем время. Сделка, пока покупка >= продажи. Цена — у заявки, которая уже стояла. Объём = min(qty_left). Свой счёт со своим не сводится.
```
notional = price * qty
fee = (notional * fee_bp) // 10000
```
Покупка заранее блокирует `limit_price * qty` на escrow. Разница лимита и цены возвращается.

**Пример 3.** Продажа 900 ₽ уже в стакане. Лимит покупки 1000 ₽, qty 4, резерв 4000. Цена 900, notional 3600, fee = (3600 * 10) // 10000 = 3. Продавец +3597, казна +3, сдача 400. 3597 + 3 + 400 = 4000.
**Пример 4.** notional 300 → fee = (300 * 10) // 10000 = 0. Floor, минимальной комиссии 1 ₽ нет.

### Полоса, капитализация, дивиденд, поглощение
```
min_px = (last * 800) // 1000
max_px = (last * 1200) // 1000
cap = last * total_shares
distributable = (profit_after_tax * payout_‰) // 1000
per_share = distributable // total_shares
paid_total = per_share * total_shares
holding_bp = (shares_owned * 10000) // total_shares
```
Дивиденд только при прибыли > 0. Если cash меньше paid_total, per_share считается от cash тем же делением. Прибыль уже после 1500 bp (09) и налога города (14); пока 14 выключен, налог города в базе 0.

**Пример 5.** last 1000 → коридор 800…1200, заявка 1300 отклоняется. cap = 1 000 000. last 999 → min 799, max 1198.
**Пример 6.** profit 100 000. Федеральный (100000 * 1500) // 10000 = 15 000. Город (100000 * 500) // 10000 = 5 000. После налогов 80 000. payout 250 ‰, 300 акций. distributable = (80000 * 250) // 1000 = 20 000. per_share = 66. paid = 19 800. remainder = 200 остаётся в компании.
**Пример 7.** 600 из 1000 → 6000 bp, контроль есть, если в холдинге есть слот. 499 из 1000 → 4990 bp, нет. Оферта 500 ₽ × 600: gross 300 000, fee 300, продавцы 299 700. Арифметика проверена дважды.

## Тики и реестр

Часового тика нет (GDD 00). `share_match` — раз в игровой день, после `projects` и до `events`. Шаг `stock` — это запасы, его не занимать. Внутри: снять просроченный резерв, свести стакан, записать сделки.

Месячный шаг: дивиденды сразу после налога города (14) и до банкротства (09). Повтор month_index вторую выплату не делает.

## Защита от злоупотреблений

- 101-я заявка за день → отказ, резерва нет. Продажа только в пределах shares − qty_locked. Короткой продажи нет.
- Покупка без полной блокировки денег не создаётся. Вне полосы 800–1200 ‰ — отказ. qty от 1 до 10 000 (balance: draft).
- Один owner не сводится сам с собой.
- request_id обязателен на IPO, заявку, отмену, дивиденд и оферту. Тот же id и то же тело — прежний результат, без второй проводки. Другое тело → 409.
- Отмена `share_release:<order_id>` возвращает резерв один раз. Одно IPO. Один dividend_run на компанию и месяц.

## Проводки ledger

- Резерв: покупатель −reserve, escrow +reserve. `share_reserve:<request_id>`.
- Сделка: escrow −notional, продавец +(notional − fee), treasury +fee, сдача покупателю.
- IPO: инвесторы −gross, компания +net, treasury +fee. `ipo:<company_id>`.
- Дивиденд: компания −paid_total, держатели +per_share. `dividend:<company_id>:<month_index>`.
- Отмена: escrow −reserve, покупатель +reserve.

Нехватка денег или акций: проводки нет, счёт не в минус. Сумма каждой проводки 0.

## API

- GET /market/shares/{company_id} — стакан, last, cap
- POST /market/ipo, POST /market/order, POST /market/order/{id}/cancel, POST /companies/{id}/dividend, POST /market/tender
- Тело заявки: company_id, side, limit_price, qty, request_id. Дивиденд: payout_‰, request_id (выплата в месячном шаге, не в POST)
- Ошибки: 400, 402, 409, 429

## Что показывает клиент

Экран «Акции», не «Биржа»: стакан, last, капитализация, пакеты, ближайший дивиденд. Пусто: «Нет размещённых компаний».

## Открытые вопросы

D-41. IPO только в M4? Рекомендация: да. Раньше нет устойчивой прибыли и холдинга, стакан будет пустым. Срочность: позже.
D-42. Лимит 100 заявок в день? Рекомендация: да. Хватает торговать и мало, чтобы забить стакан. Срочность: позже.
D-43. Комиссия 10 bp? Рекомендация: да, только floor. Оборот < 1000 ₽ даёт 0 ₽; минимальную 1 ₽ не вводить без отдельного решения. Срочность: позже.
D-62. Дивиденды обязательны? Рекомендация: нет. payout_‰ = 0 законен, иначе нельзя копить на стройку. Срочность: позже.
D-71. Поглощения в бете? Рекомендация: только порог 5000 bp и свободный слот холдинга, без защиты миноритариев. Срочность: позже.
D-77. Минимальный лот? Рекомендация: 1 акция. Дробных нет, порог выше отсечёт малых игроков. Срочность: позже.
D-78. Что торгуется? Рекомендация: только акции компаний. Город, земля и товары остаются в своих модулях. Срочность: позже.
D-79. Полоса ±200 ‰? Рекомендация: да. Одна заявка не рисует свечу далеко от last. Срочность: позже.
