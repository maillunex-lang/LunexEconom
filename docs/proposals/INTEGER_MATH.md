# Правила целочисленной арифметики (INTEGER_MATH)

Все деньги, коэффициенты, проценты и расчёты в игре — целые числа (bigint). Float, дробные ставки и логарифмы запрещены. Этот файл — единый источник правил для модулей 07–10 и далее.

## Базовые единицы

- **Деньги**: целые игровые рубли (1 игр. ₽ = 50 реальных). Нет копеек.
- **Базисные пункты (bp)**: 1 % = 100 bp. Пример: 12 % годовых = 1200 bp. Месячная ставка = годовая_bp / 12 (целое деление с floor).
- **Промилле (‰)**: 1 ‰ = 0.1 %. Для множителей: factor_permille, где 1000 = ×1.0.
- **Проценты целые**: для весов рейтинга, долей населения и т.п. (0–100).

## Округление

**Правило:** все деньги округляются вниз (floor). Остаток от округления остаётся у плательщика (или в системном счёте, если плательщик — система).

Формула:
```
result = (numerator * multiplier) // divisor   // floor
remainder = (numerator * multiplier) % divisor
```
Остаток не списывается с плательщика.

Пример: налог 15 % от 1000 ₽ → 150 ₽. От 1001 ₽ → 150 ₽ (остаток 1 ₽ у компании).

## Аннуитетный платёж кредита (целочисленный)

Не используем формулу с степенями. Метод: каждый месяц считаем проценты от остатка долга, платёж = проценты + часть тела, округление floor. Последний платёж закрывает остаток.

Алгоритм:
1. monthly_rate_bp = annual_rate_bp // 12
2. Для каждого месяца: interest = (balance * monthly_rate_bp) // 10000
3. payment = фиксированный или рассчитанный так, чтобы закрыть за N месяцев (черновой график генерируется заранее или на лету).
4. Последний payment = остаток + interest этого месяца.

**Численный пример** (кредит 1 000 000 ₽, 1200 bp годовых, 12 месяцев):
- monthly_rate_bp = 1200 // 12 = 100 bp (≈ 1 % в месяц).
- Платёж фиксируем как ~88 848 ₽ (подбор под закрытие, balance: draft).
- Месяц 1: interest = (1000000 * 100) // 10000 = 10 000; тело = 78848; остаток 921 152.
- Далее аналогично, последний платёж добивает остаток до нуля.
Все операции floor, сумма платежей чуть больше идеального аннуитета из-за округления — это нормально.

## Порядок операций

1. Умножение на множитель (в bp или промилле).
2. Деление целочисленное (//).
3. Clamp к минимуму/максимуму (целые границы).
4. Применение к деньгам с floor.

Переполнение bigint не допускается: все промежуточные произведения должны вмещаться в 64-битное целое с запасом. При сомнении — ошибка сервера.
