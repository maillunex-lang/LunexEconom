# Правила целочисленной арифметики (INTEGER_MATH)

Все деньги, коэффициенты, проценты и расчёты в игре — целые числа (bigint / i64 с запасом). Float, дробные ставки, логарифмы и записи вида `1e6` запрещены. Этот файл — единый источник правил и констант для модулей 07–16.

## Базовые единицы

- **Деньги**: целые игровые рубли. Нет копеек. 1 игр. ₽ = 50 реальных (по соглашению с директором).
- **Базисные пункты (bp)**: 1 % = 100 bp. Пример: 12 % годовых = 1200 bp. Месячная ставка = годовая_bp // 12 (целое деление floor).
- **Промилле (‰)**: множители, где 1000 = ×1.0. Применение: `result = (value * factor_‰) // 1000`.
- **Проценты целые**: для весов, долей (0–100).

## Округление

**Правило:** все деньги округляются вниз (floor). Остаток от округления остаётся у плательщика (или в системном счёте, если плательщик — система).

```
result = (numerator * multiplier) // divisor   // floor
remainder = (numerator * multiplier) % divisor
```
Остаток не списывается дополнительно с плательщика.

Пример: налог 15 % (ставка 1500 bp) от 1000 ₽ → 150 ₽. От 1001 ₽ → 150 ₽ (остаток 1 ₽ у компании).

## Аннуитетный платёж кредита (целочисленный)

Не используем формулу со степенями. Метод: каждый месяц считаем проценты от остатка долга, платёж = проценты + часть тела, округление floor. Последний платёж закрывает остаток.

Алгоритм (псевдокод):
```
monthly_rate_bp = annual_rate_bp // 12
balance = principal
for month in 1..N:
    interest = (balance * monthly_rate_bp) // 10000
    if month == N:
        payment = balance + interest
    else:
        payment = fixed_payment   // подобранный или рассчитанный заранее
    principal_part = payment - interest
    balance = balance - principal_part
    if balance < 0: balance = 0
```
Все операции floor. Сумма платежей чуть больше идеального аннуитета из-за округления — норма.

**Численный пример** (кредит 1 000 000 ₽, 1200 bp годовых, 12 месяцев):
- monthly_rate_bp = 1200 // 12 = 100 bp.
- Месяц 1: interest = (1000000 * 100) // 10000 = 10 000; тело ≈ 78 849; остаток 921 151.
- Далее аналогично, последний платёж добивает остаток до нуля.
Подробный график генерируется при выдаче и сохраняется.

## Порядок операций

1. Умножение на множитель (в bp или промилле).
2. Деление целочисленное (//).
3. Clamp к минимуму/максимуму (целые границы).
4. Применение к деньгам с floor.

Промежуточные произведения должны вмещаться в 64-битное целое с запасом. При сомнении — ошибка сервера.
