# ChatGPT8: строительство и дорожная геометрия (15.11.2026)

## Реализовано и проверено
- `client/world.gd` использует GLB `road_corner_1x1` для угловой дороги и выбирает поворот по битовой маске четырёх соседей. Как и другие дороги, геометрия объединяется через MultiMesh.
- Для события `building_created` и chunk snapshot клиент принимает необязательное поле `construction_stage`. Значения `foundation` и `frame` у зданий размера 3×2 выбирают соответствующий GLB; `complete` или отсутствующее поле отображают обычное готовое здание. Размер участка и владелец не меняются.
- При изменении стадии визуальная сигнатура объекта меняется, модель перестраивается; проверены три перехода `foundation → frame → complete` через тестовые события.
- `client/tests/world3d_smoke.gd`: `WORLD3D_SMOKE_PASS`.
- `client/tests/build_menu_smoke.gd`: `BUILD_MENU_SMOKE_PASS`.
- Серверный регресс: **542 tests, 55 skipped, 0 failures**.
- `client/tests/asset_runtime_smoke.gd`: ранее `ASSET_RUNTIME_SMOKE_PASS count=7`.
- 60 GLB проверены; улучшены модели грузовика и трактора.

## Ограничения, требующие отдельной реализации
- Текущий сервер SQLite/PostgreSQL **не выдаёт** `construction_stage` в обычных ответах. Это подготовленный клиентский контракт, а не завершённая серверная система строительных сроков.
- Нет отдельного серверного авторитетного таймера стройки, миграций состояний и событий `foundation/frame/complete`; нельзя выдавать клиентскую поддержку за полноценную синхронизацию.
- Транспорт остаётся статическим ресурсом, без AI маршрутизации и анимации.
- GitHub Actions фактические результаты и Android APK acceptance не подтверждены.
- PostgreSQL 200-операционный тест с одним IP ограничен штатным 120/min/IP rate limiter. Полный многоклиентский прогон не завершён.

## Границы изменений
Работа опубликована только в `ChatGPT8`. Рабочие VPS сервисы, production DB, nginx и `main` не менялись.
