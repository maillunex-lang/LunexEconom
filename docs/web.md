# Статический лендинг V2, Forest Glass

Ветка разработки: `v2/landing`. Лендинг полностью автономен, только на русском языке, без cookies, CDN, внешних шрифтов и трекеров. Никакого подключения к игровым сервисам. Страница рассчитана на размещение **внутри** `https://rikagro.ru/lunexeconom/`, а не в корне `rikagro.ru`. `web/roadmap.json` и `docs/content/**` принадлежат директору; в этой задаче не изменялись.

## Файлы и размещение

Каталог `web/` содержит `index.html`, `styles.css`, `config.js`, `site.js`, `roadmap.json`. Отдельные файлы `update.json` и `update.json.sig` предоставляет владелец после создания **подписанного** выпуска. APK располагается по URL из манифеста, обычно `https://rikagro.ru/lunexeconom/download/lunex.apk` и физически в каталоге `download/` под базовым URL; в исходных файлах web/ **нет** APK и нет фиктивного `update.json`.

Владелец отдельно разворачивает статику из архива на целевой сервер только в **части C**, после явной команды. В рабочем дереве развертывания нужно расположить файлы `web/*` в директории, которую будущий согласованный серверный конфиг уже сопоставит `/lunexeconom/`. Ни SSH, ни nginx, ни systemd не настраиваются этой задачей. Пути в HTML, JavaScript и CSS относительны (`./roadmap.json`, `./update.json`, `./styles.css`); адрес базовой папки изменяется только в `web/config.js`. Рекомендуется проверить доступность страницы с завершающим `/`, чтобы браузер верно разрешал относительные пути.

**Ручная проверка:** `python3 -m http.server 8080 --directory web`, открыть `http://localhost:8080/`. Чтобы воспроизвести реальную подпапку, использовать тестовый сервер в `web/tests/smoke.cjs`. CI строит снимки при 360×800 и 1440×900 в светлой и тёмной темах.

## Актуальный APK

При открытии сайт выполняет `fetch("./update.json", {cache:"no-store"})`. Поля формата выпуска из `docs/release.md`: `version_name`, `size` (байты), `released` (ISO-8601), `notes`, `sha256` (64 шестнадцатеричных символа), `apk_url` (полный HTTPS URL), `version_code` и `min_version_code` (последние два нужны игре). Сайт отображает версию, дату, размер, заметки, хеш SHA-256, ссылку на APK, и до пяти записей журнала. По умолчанию журнал включает один текущий выпуск. Для будущего списка допускается необязательный `releases` или `history` с `version_name`, `released`, `notes`, но **это расширение не входит в текущую обязательную спецификацию подписанного манифеста** и требует утверждения владельца/директора и согласования с валидатором подписей клиента.

Сайт принимает ссылку на APK, только если это абсолютный HTTPS URL с тем же origin, что и `window.LUNEX_PUBLIC_BASE`, и путь строго внутри его директории, оканчивается `.apk`, без credentials, query, hash или path traversal. Подпись RSA браузер не проверяет: **проверять происхождение APK и соответствие SHA-256 пользователь должен самостоятельно; клиент проверяет RSA при обновлении внутри игры**. Не трактовать просто доступный JSON как доказательство подлинности. При недоступном JSON или непрошедшем проверку URL кнопка ведёт на `window.LUNEX_FALLBACK_RELEASE` (`https://github.com/maillunex-lang/LunexEconom/releases/latest`) и не отключается; наличие там релиза сайт не гарантирует. При наличии корректной ссылки кнопка остаётся активной и называется «Скачать для Android». Сообщение об ошибке не содержит выдуманной версии.

**Атомарное обновление выпуска владельцем в части C, после офлайн-подписи:** заранее приготовить APK и вычислить SHA-256, сверить его с `update.json`, подписать точные канонические байты JSON приватным офлайн-ключом, проверить `.sig` публичным ключом и не передавать приватную часть на VPS. Загружать на сервер сначала APK в временное имя и атомарно переименовать после полной передачи, затем подготовить временные `update.json.new` и `update.json.sig.new`. До публикации убедиться, что оба подготовленных файла образуют корректную пару, и затем атомарно переименовать подпись и **последним** манифест (в установленной последовательности «сначала файл, затем подпись» имеется краткое окно несогласованности; безопаснее два временных файла и публикация манифеста последним). Настроить `Cache-Control: no-store` для манифеста и подписи, HTTPS и права доступа, не трогая другие пути домена. Вариант надёжнее для отсутствия окна: переключение целого каталога двух файлов и APK через атомарный симлинк, если будущая схема nginx это поддерживает. Не начинать публикацию до согласования процедуры владельцем.

## Дорожная карта

Данные приходят только из `./roadmap.json`. Все поля читаются как текст через `textContent`, не через `innerHTML`. При отсутствии сети отображается сообщение о недоступности данных, без ложного утверждения актуального процента. Без JavaScript существует статичная копия в HTML, соответствующая `roadmap.json` на 2026-11-15. Её нужно синхронизировать при изменении директором JSON; только директор меняет реальные статусы и проценты. При доступном JS карта отрисовывает 5 вех, карточки фаз и их пункты, управляемые нативным `details`/`summary` с клавиатуры, и легенду.

**Формула готовности:** для N фаз с `progress` от 0 до 100: `P = round((progress₁ + ... + progressₙ) / N)`, веса равные, округление до ближайшего целого (для неотрицательных чисел `Math.round`). На дату исходного файла: `(100 + 100 + 15 + 0 + 0 + 5 + 2 + 0) / 8 = 27,75`, показано **28%**. Вехи в расчёт не входят. Дату обновления берём из `updated`, а не из часов устройства.

В `web/roadmap.json` статус каждой вехи, фазы и пункта ровно `done`, `wip` или `planned`. Прогресс фазы целый 0–100, заголовки непустые, ссылка фазы на milestone действительна. Инфографика CSS: горизонтальная шкала вех, круги на `conic-gradient`, подписи статусов словами. В 360 px шкала прокручивается по горизонтали **внутри собственного блока**, не растягивая страницу. `prefers-reduced-motion` отключает анимации. Тема следует системной и переключается локально, без cookies/localStorage.

**Обновление roadmap:** директор утверждает изменения, корректирует только `web/roadmap.json`, проверяет `python3 tools/check_website.py`, при необходимости обновляет встроенную HTML-копию данных для пользователей без JS, фиксирует commit и запускает `website-check`. Только после этого владелец вручную публикует новую версию файлов отдельной командой. `roadmap.json` следует помещать под временным именем и атомарно переименовывать, не допуская частично записанного JSON.

## Проверки

```sh
python3 tools/check_website.py
python3 -m unittest tools.tests.test_website -v
node --check web/site.js
node --check web/tests/smoke.cjs
```

CI `website-check.yml` ставит Playwright Chromium, проверяет три варианта: манифест доступен, отсутствует, содержит чужой URL. Для каждого снимки 360×800 и 1440×900 в обеих темах, проверка правильной кнопки, отсутствия console errors и переполнения. Также открывает страницу с выключенным JavaScript. Артефакт `website-screenshots` хранит PNG. Ручной `website-bundle.yml` проверяет данные, формирует `lunexeconom-website.tar.gz` с `web/` и `SHA256SUMS.txt`, загружает оба как Actions artifact. **Workflow не публикует файлы на VPS и не содержит SSH.**

## Предложения директору (без изменения формата roadmap.json)

1. Рассмотреть поле `summary` для краткого описания фазы и поле `target_version` для привязки к релизу; пока карта использует существующие `title/status/progress/items`.
2. Рассмотреть генерацию статической HTML-копии из JSON как отдельный CI-артефакт или серверный build step (без клиентской зависимости JS), чтобы no-JS версия не старела.
3. Если потребуется полноценный журнал, утвердить расширение подписанного `update.json` с необязательным `releases` (максимум 5), обновить серверный/клиентский валидатор отдельно, а сайт уже умеет показывать список.
