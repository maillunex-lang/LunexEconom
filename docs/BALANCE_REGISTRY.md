# Реестр баланса

Файл `server/balance.py`. Одно место для налогов, труда, кредитов, миграции, розницы, трат владельца, стройки старых зданий, перевозки, зон (как зеркало), качества и исследований. `docs/BALANCE_PLAN.md`, раздел 4.

Константы `server/economy.py` остаются под прежними именами и при импорте копируются из реестра. Значения по умолчанию те же, что были в коде: зарплата 1 500, стартовый капитал 1 000 000, налог на прибыль 13 %, имущество 2,2 %, НДС-потолок 22 %, наценка магазина 30 %, доля трат владельца 0,35, границы цены 0,25…2,5.

Переопределение до старта процесса:

- переменная `LUNEX_BAL_<ИМЯ>`, например `LUNEX_BAL_BASE_WAGE=1600`;
- файл `LUNEX_BALANCE_FILE` — JSON-объект, лишние ключи игнорируются. Переменная окружения важнее файла.

Уже запущенный процесс не перечитывает числа в `economy` (они скопированы при импорте). `balance.reload()` обновляет только реестр.

Чего реестр не переключает сам:

- `regions.SPEED_KMH` и `regions.TRANSPORT_COST_PER_KM` по-прежнему живут в `regions.py` (этот файл не менялся). В реестре те же числа лежат как справка. Грузовики читают `TRUCK_*`.
- `zoning.CORE_SHARE`, клин и рост живут в `zoning.py`. В реестре это `ZONE_*`, код зон их не читает.

Новые ручки этой ветки: `TRUCK_CAPACITY` 40, `TRUCK_PRICE` 80 000, `TRUCK_UPKEEP` 2 000, `TRUCK_COST_PER_KM` 8, `QUALITY_PRICE_STEP` 0,05, `RESEARCH_COST` 80 000, `RESEARCH_MONTHS` 2, `RESEARCH_INPUT_RELIEF_PERMILLE` 100, `NPC_NEW_KINDS` 0.

`GET` группы — `balance.public_view()` (труд, миграция, налоги, кредит, розница, траты, стройка, перевозка, зоны, качество). Отдельного HTTP нет: клиенту хватает чисел в `GET /trucks` и `GET /catalog/goods`.
