# Отчёт симулятора баланса

Инструмент: `tools/balance_sim.py`. Отчёт перегенерирован после правок баланса (см. «Главное»); первый вариант отчёта (до правок) — в истории git, коммит `fe00116`.
Мир считается на временной SQLite вызовами `production.advance` (внутри — `step_month`);
часы подменены, реальная пауза не используется. NPC ходят через `npc.tick` (ошибка не глотается,
в отличие от `game_server.npc_tick`). Сумма всех проводок и сумма всех кошельков должны быть 0:
стартовый капитал, кредиты и оплата рынком — двойная запись, а не дырка в журнале.
Цена, налоги, население и проводки месяца — это закрытый месяц. Число зданий и деньги
сняты сразу после решений NPC и ботов на границе следующего месяца (так же сервер
вызывает npc_tick перед действием игрока), поэтому новое здание ещё не входило в выпуск.

Воспроизведение одного прогона:

```bash
cd tools && python balance_sim.py --months 72 --seed 20261114 --csv /tmp/npc72.csv
cd tools && python -m unittest discover -p 'test_*.py' -v
```

Пороги красных флагов: цена на границе 6 мес. подряд; качели потолок/ниже склада — от 4 раз;
население > 1600; шаг месяца > 500 мс; все 3 NPC без зданий после банкротства;
бюджет города < 0; 3 и больше банкротств за один месяц.
Границы цены: мёд 50–500, нефть 375–3750, товары 500–5000.

## Главное

Первый прогон (коммит `fe00116`) нашёл три проблемы поведения. После правок на тех же четырёх сценариях (seed и параметры те же):

| Сценарий | Красных флагов до | после | Что осталось |
|---|---:|---:|---|
| npc_72 | 2 (`price_whipsaw`, `open_loop`) | **0** | — |
| bots_72 | 2 (`price_whipsaw` мёда 17 раз, `open_loop`) | **0** | — |
| expand_48 | 3 | **1** | `mass_default` месяц 6 |
| credit_60 | 3 | **1** | `mass_default` месяц 6 |

Инварианты журнала (сумма проводок и кошельков = 0, нет отрицательных запасов) по-прежнему 0 нарушений. Шаг месяца на 1000 зданий ≈ 18 мс.

1. **Качели складов — исправлено.** Склад удерживает долю выпуска, пропорциональную глубине падения среднего цены за 3 месяца (весь выпуск — только при цене ≤ 0,45 от базовой), и выпускает запас по 34 % в месяц, а не разом (`economy.HOLD_DEPTH/HOLD_SMOOTH_MONTHS/RELEASE_SHARE`, `production._hold_share`). Перебор 18 комбинаций параметров и 10 дополнительных прогонов (seed 1–5, две стратегии): качелей нет. Выбрано значение `HOLD_DEPTH=0.5`.
2. **Жители тратят зарплату — исправлено частично.** Каждый месяц жители тратят зарплату на потребительский спрос: `system:residents → system:market`, не больше остатка на счёте жителей. Накопленных нетраченых зарплат больше нет (0 вместо 10–20 млн ₽). **Но `system:market` по-прежнему уходит в минус (≈ −25…−39 млн ₽ за 48–72 месяца):** выручка производителей больше, чем зарплаты жителей, и разницу — прибыль владельцев — рынок оплачивает из ничего. Полностью замкнуть круг можно только стоком, куда тратят прибыль владельцы (дивиденды, личное потребление, налог на доходы); это отдельное решение владельца, не сделано.
3. **Кредит при банкротстве — исправлено.** Безнадёжный долг списывается в журнале: потери банка покрывает казна Республики (`bank.write_off`: `system:treasury → system:bank`). `system:bank` больше не остаётся отрицательным без живых кредитов (в credit_60: −688 689 ₽ до, +147 816 ₽ после — это проценты банка). Убытки теперь видны в `system:treasury`.
4. **`mass_default` — не менялось.** Одинаковые боты «бери максимум кредита и строй самое дорогое» банкротятся в один месяц (6); это поведение стратегии, а не ошибка движка: банкротство и ликвидация работают штатно, NPC живы. Если нужно смягчить для игроков, вариант — лимит кредита по сроку жизни компании или по доходу; решение за владельцем.

## Длина месяца

Действия стоят на границе месяца (доля месяца = 0), поэтому экономика не должна
зависеть от `LUNEX_MONTH_SECONDS`. Отличается только подпись часов.

- **86400 с = 60 с** по всем целым метрикам.
- **86400 с = 600 с** по всем целым метрикам.

## Производительность шага

Здания вставлены напрямую в `buildings` / `building_ops` (без поиска дороги),
примерно по 10 на компанию, у каждой стартовый капитал. Замеряется один `production.advance`
ровно на один игровой месяц. Это стоимость месячного расчёта, не стоимость стройки.
