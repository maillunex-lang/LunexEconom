# Operations V2: подготовка перехода без исполнения части C

**Запрет:** до отдельного сообщения владельца «выполняй часть C» не запускать развёртывание, не создавать БД/пользователя, не менять systemd, nginx, автообновление и данные старого мира. Выполнение V2-00 на GitHub само по себе не разрешает менять VPS. Для локальной разработки использовать отдельную непроизводственную среду.

## Порядок будущей части C (только план)

1. Проверить процессы, `systemctl` и конфигурацию nginx без вывода секретов; установить точные пути V1, существующий port, updater и источники резервных копий. До изменения сделать подтверждённую резервную копию старой PostgreSQL средствами `pg_dump -Fc` с проверкой `pg_restore -l`, отдельно архив server/ и nginx-конфигурации; хранить вне изменяемого каталога.
2. Создать в PostgreSQL 16 отдельные **`lunex_v2`** и `lunex_v2_app` с новыми правами исключительно на V2, без доступа к базе V1. DSN хранить вне Git, например в `EnvironmentFile` с правами 0600. Старые аккаунты и мир не копировать.
3. Создать отдельный каталог приложения `/opt/lunexeconom-v2` и state `/var/lib/lunexeconom-v2-update`, пользователь `gamedev` без расширения прав, systemd `lunexeconom-v2.service` с отдельным loopback-портом `18777` (предварительно убедиться, что он свободен). Приложение проверить с `curl -fsS http://127.0.0.1:18777/health`; сервис V1 не трогать.
4. Перед переключением nginx назначить отдельный **временный** маршрут V2 `/lunexeconom/v2/api/` → `127.0.0.1:18777`, старый `/lunexeconom/api/` оставить на V1. Проверить каждый URL, регистрация/вход только в V2, затем в согласованное окно перевести `/lunexeconom/api/` на V2. При этом сохранить старый маршрут `/lunexeconom/v1/api/` → V1 до отдельного решения об отключении. Контролировать обработку префиксов и CORS. Сначала `nginx -t`, затем разрешённый reload.
5. Создать **отдельный** экземпляр updater с `LUNEX_SERVER_DIR=/opt/lunexeconom-v2/server`, `LUNEX_UPDATE_STATE=/var/lib/lunexeconom-v2-update`, `LUNEX_SERVICES=lunexeconom-v2.service`, `LUNEX_HEALTH_URL=http://127.0.0.1:18777/health`. Автообновление V1 остановить/зафиксировать по отдельному решению владельца, исключить возможность получения orphan `main` старым updater. Никогда не указывать каталог/сервис V1 как цель нового updater.
6. Проверить HTTP, журналы, доступ V1 и V2 по отдельным путям. Обновить настройки клиента только после публикации корректного APK. В случае неуспеха восстановить предыдущий nginx upstream и состояние V2 из собственной резервной копии; V1 и её БД оставить нетронутыми.
7. Отключение старого сервиса и старой базы только после пользовательской приёмки новой версии и отдельного разрешения. Архивный Git branch/tag никогда не удалять.

## План отката

Сохранить последнее работающее состояние nginx, systemd и SQL-дамп V1; V2 updater хранит versioned backup под `/var/lib/lunexeconom-v2-update/backups`. При провале health updater автоматически восстанавливает файлы V2 и перезапускает V2. При проблеме с nginx вернуть старую конфигурацию и `nginx -t`, затем reload; V1 живёт независимо. Дамп V1 нужен как аварийная страховка, не как источник миграции аккаунтов.

## CI gate

На каждую новую серверную версию требуется успешный workflow `server-check.yml` точно на целевом SHA. Updater не разворачивает непроверенный SHA и сохраняет состояние для отката. Нельзя использовать «нет workflow → всё в порядке».
