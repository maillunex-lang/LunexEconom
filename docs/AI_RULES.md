# Правила работы исполнителей V2 (ChatGPT)

Директор проекта (Claude) пишет спецификации (`docs/gdd/`, `docs/spec/`), раздаёт задания, принимает работу. Владелец решает по продукту и подтверждает слияния. Этот файл заменяет правила V1 (они сохранены в `archive/v1`).

## 1. Ветки и слияние
Задание содержит имя ветки. Ветка от свежего `main`; коммиты небольшие и логичные; **в `main` не пушить**: отчёт с SHA и «можно принимать», директор проверяет и сливает. **Постоянное разрешение владельца (2026-11-15):** директор вправе сливать в `main` сам, когда приёмка пройдена (зона файлов соблюдена, тесты и CI зелёные, конфликтов нет, отчёт честный). Остаются ТОЛЬКО по прямой команде владельца: изменения VPS и боевых сервисов (часть C), смена и перенос ключей подписи, финальное переключение V1/V2, вайп мира и удаление данных, публикация релиза не по плану. Перед отчётом влить свежий `main`, разрешить конфликты без потери чужого, прогнать все проверки.

## 2. Безопасность
Не менять боевой сервер, базы, nginx, systemd, ключи; часть C (VPS) только по явному «выполняй часть C» владельца. Секреты не в репозиторий и не в чат. Мир V1 и его база не трогаются, аккаунты не переносятся.

## 3. Архитектура (кратко, подробности в `docs/ARCHITECTURE.md`)
PostgreSQL 16 единственная база (в тестах изолированная); модули-пакеты `server/<модуль>/`; регистрация маршрутов, миграций, тиков и флагов через `server/registry.py`; миграции `YYYYMMDDHHMM_модуль_описание.sql`; единый каталог `server/data/*.json`; деньги целые, двойная запись, идемпотентность по `request_id`; время по `docs/spec/TIME_MODEL.md`.

## 4. Зоны файлов
Исполнитель владеет **только** файлами своего модуля: `server/<модуль>/`, `server/migrations/*_<модуль>_*.sql`, `server/tests/test_<модуль>_*.py`, `server/data/<свои файлы>.json`, `docs/<модуль>.md`, клиентские файлы своего экрана. Общие файлы (`server/registry.py`, `server/game_server.py`, `server/db.py`, `.github/workflows/*`, `docs/PROGRESS.md`) меняются **минимально и аддитивно** (одна-две строки подключения модуля); чужие модули не редактируются, нужные изменения описываются в отчёте.

## 5. Тесты и приёмка
Каждая функция имеет тест; интеграционные на PostgreSQL; критерии приёмки модуля из `docs/gdd/NN_*.md` проверяются тестами; `server-check`, `client-check`, `website-check`, сборка APK зелёные. Баланс чисел откладывается до заморозки функционала (раздел вех в `docs/gdd/00_OVERVIEW.md`), но инварианты (сумма проводок 0, идемпотентность, отсутствие отрицательных запасов) проверяются всегда.

## 6. Клиент
Только Android, горизонтально, safe area, Godot 4.7, стиль Forest Glass, данные с сервера, 2.5D карта и штаб-квартира по `docs/spec/PRODUCT.md`; без постоянных анимаций вне карты.

## 7. Отчёт
SHA и ветка, список файлов по зонам, что сделано и как проверено (команды, ключевой вывод), что не сделано, найденные проблемы в чужих зонах, что нужно директору. Не заявлять готовность без работающей реализации и тестов.
