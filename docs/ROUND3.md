## Общие правила (обязательны для всех трёх)
1. **Работать только в своей ветке** (от свежего `main`). В `main` не пушить, **PR не создавать и не сливать**; слияние делает Claude по команде владельца. Чужие ветки не трогать.
2. **Зона файлов.** Меняй только файлы своей зоны и **новые** файлы. В общих файлах (`server/game_server.py`, `server/postgres_world.py`, `server/postgres_db.py`, `client/world_screen.gd`, `.github/workflows/server-check.yml`, `docs/ROADMAP.md`) — **только добавление** небольших блоков в конец своего раздела, без переформатирования и перестановки чужого: так конфликты при слиянии тривиальны.
3. **Имена без коллизий.** Новые таблицы БД — с префиксом своей ветки (`ops_*` у ChatGPT, `eco_*`/существующие у Grok1, `soc_*` у Grok2). Новые endpoint-ы — в своём пространстве (`/soc/...`, `/eco/...`). Новые панели клиента — отдельными файлами `client/<name>_panel.gd`, подключение в `world_screen.gd` одним добавочным вызовом и одной кнопкой.
4. **Две БД.** Любая серверная логика работает на SQLite и PostgreSQL одинаково (модуль принимает `db` и плейсхолдер `ph`); тест на SQLite + `test_postgres_*` (пропускается вне `lunex_ci`); SQLite-соединения только через `sqlite_util`. Деньги — целые рубли, двойная запись `economy.post`, сумма проводок 0, идемпотентность по `request_id`.
5. **Окна клиента** строятся по образцу `leaderboard_panel.gd` / `contracts_panel.gd`: размер `host.panel_rect(...)`, заголовок с «Закрыть» неподвижен, тело в `ScrollContainer`; скрытая панель не принимает касания. Каждый новый экран — headless-смоук `client/tests/<name>_smoke.gd` (по образцу `scroll_panels_smoke.gd`: **завершать `quit()` и в ветке ошибки**, иначе тест виснет).
6. **Проверки перед отчётом (все обязательно):**
   `cd server && python -W ignore -m unittest discover -p 'test_*.py'` · `cd ops && python -m unittest discover -p 'test_*.py'` · `cd tools && python -W ignore -m unittest discover -p 'test_*.py'` ·
   тесты PostgreSQL на **одноразовой** базе `lunex_ci` (никогда на боевой) · `godot --headless --path client --import` без `SCRIPT ERROR` · все смоуки из `client/tests/`.
   Ничего не помечать «готово» без реально запущенных тестов; что не проверено — писать прямо.
7. **Секреты, боевая БД, VPS, чужие сервисы** — не трогать. Ключи, пароли, токены — только через переменные окружения, не в репозиторий.
8. **Периодически** `git fetch origin && git rebase origin/main` (main может ходить вперёд: Claude правит только по замечаниям).
9. **Отчёт.** Журнал `docs/PROGRESS_<ИМЯ>.md` в своей ветке (дата, что сделано, файлы, точные команды и результаты, что не проверено, риски). Итог — сообщение владельцу: **итоговый SHA ветки**, список изменённых общих файлов (хуки), результаты тестов SQLite/PostgreSQL/Godot, что осталось. Если правило игры неясно — спроси, не угадывай.
10. **Порядок и честность.** Делай задачи по порядку из брифа; закончил пункт — тесты и запись в журнал, затем следующий. Не выдавай нереализованное за готовое.
