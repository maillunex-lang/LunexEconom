# План работ: этапы и две независимые линии исполнителей

Источник правды: [`work_plan.json`](work_plan.json). Файл собирается командой `python tools/work_plan.py render`, вручную не правится. Проверка `python tools/work_plan.py check`.

Две линии работают одновременно и не пересекаются по файлам: **A (Сервер)** и **B (Клиент)**. Линия B строит экраны по контрактам из GDD на моках (mock-first), поэтому не ждёт сервер. Директор проектирует, проверяет и сливает в `main`; исполнители работают в своих ветках `v2/<id>-<slug>` и не меняют общие файлы.

## Линия A: Сервер (ChatGPT №1)
Только сервер, миграции, серверные тесты и документация модулей.

Зона файлов: `server/**`, `tools/loadtest/**`, `docs/qa/*.md`, `docs/enterprises.md`, `docs/supply.md`, `docs/retail.md`, `docs/platform.md`, `docs/world.md`, `docs/admin.md`, `web/admin/help.js`, `.github/workflows/server-check.yml`

## Линия B: Клиент (ChatGPT №2)
Только клиент Godot, строки интерфейса и клиентские тесты. Сервер не трогает: работает по контракту GDD через моки (mock-first).

Зона файлов: `client/**`, `docs/content/ui_strings.ru.md`, `docs/qa/*.md`, `tools/build_strings.py`, `.github/workflows/client-check.yml`

## Правила

1. Выдавать только пакеты со статусом «можно выдавать» (все зависимости готовы): `python tools/work_plan.py next`.
2. Текст задания генерируется: `python tools/work_plan.py prompt A1`.
3. Исполнитель не меняет общие файлы директора: `README.md`, `web/roadmap.json`, `docs/PROGRESS.md`, `docs/WORK_PLAN.md`, `docs/work_plan.json`, `docs/gdd/**`, `docs/PLAN_V2_CAPLAB.md`, `.github/workflows/android-*.yml`, `ops/**`.
4. Новые флаги серверных механик выключены по умолчанию; включает только владелец.
5. Слияние в `main` делает директор после пробного слияния, полного набора серверных тестов на PostgreSQL и всех клиентских проверок.

## Доска задач (страница для владельца)

Интерактивная страница с этапами по порядку, готовыми промптами, самопроверкой исполнителя, приёмкой директора и архивом. Собирается из этого плана: `python tools/work_board/build.py board.html`, публикуется как Artifact с общей базой (`db`, запись только владельцу). Состояние хранится в коллекции `tasks`, документ на пакет: `status` (`planned`, `issued`, `submitted`, `accepted`), `issuedAt`, `submittedAt`, `acceptedAt`, `merged`, `sha`, `note`. После изменения плана доску пересобирают и публикуют на тот же адрес, состояние сохраняется.
