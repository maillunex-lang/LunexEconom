# V2-UI-IMPL1: клиентские экраны GDD 30, этап 1

## Реализовано
- Карточка предприятия: переключатель «Кратко / Подробно» (первый режим по умолчанию); производственный склад с выходом в «Куда продавать», магазин с выходом в цены. Блок конкурентов отключён.
- `sales_policy.tscn`: 4 режима продажи, ограниченная сервером цена, резерв % и приглашённые, dry run и сохранение с `expected_version` и `request_id`. Русские сообщения для 401/403/404/409/ошибок; 404/выключенный флаг показывается без пугающего исключения.
- Магазин: полки, цены, складской остаток при наличии поля, собственный рейтинг и полоса из `/retail/ratings`; три составляющие рейтинга отображаются только при наличии данных. Сохранение существующим PUT `/enterprises/{id}/cells`.
- Поставщики: GET `/supply/offers`, имя/цена/качество/надёжность/расстояние/оценка только если присланы сервером; до 3 слотов на товар, сохранение PUT `/enterprises/{id}/supply` с телом `inputs` по действующему контракту сервера. Интерактивная заглушка карты.
- Русская локализация в docs/content/ui_strings.ru.md и автоматически собранном client/data/strings.json; smoke-тест в CI.

## Допущения
1. Серверный GET `/enterprises/{id}/sales-policy/{product}` в текущем коде **не отдаёт** допустимые границы цены. Клиент не подменяет их расчётом из каталога и блокирует изменение с понятным сообщением, пока API не вернёт `price_limits: {min_price,max_price}` или `min_price`, `max_price`. Это ограничение межмодульного контракта, не причина менять сервер в этом задании. Для теста используется мок, где границы присутствуют.
2. В `/supply/offers` сейчас нет полей `distance`, `score`, `name`, `is_ai`, поэтому они отображаются только при наличии данных. Отсутствие метки ИИ не означает, что предприятие управляется игроком. Надёжность показывается всем.
3. Текущий `/retail/ratings` содержит рейтинг, но не три вклада и не эталонные границы магазина. Компоненты вкладов остаются условными, нельзя вычислять клиентом несогласованную серверную оценку. Из рейтингов отображается **только собственная** строка `enterprise_id + cell_index`.
4. Существующий GET `/enterprises/{id}/supply` отдаёт `inputs` как словарь товаров, а существующий PUT ожидает объект `inputs` со списками записей. Клиент адаптирован к этому формату и старым массивам входов в тестовых моках. Сервер не менялся.
5. Кнопка карты поставщика пока показывает «Просмотр на карте появится позже»; прогнозы и графики не выводятся. Выбор внешнего предприятия по номеру из оферты не предполагает, что доступны координаты или оценка.
6. Текущий API не предоставляет надёжное сохранение произвольного выбора долей нескольких поставщиков с автоматической перебалансировкой: при выборе нового поставщика клиент явно пересчитывает доли выбранных поставщиков для данного товара равномерно (сумма 1000 промилле), сохраняя другие товары. Для произвольного распределения требуется отдельный редактор слотов; сервер отвечает за окончательную валидацию.
7. Для `private` серверный контракт разрешает `reserve_bp=10000`; для остальных режимов, кроме `mixed`, отправляется 0. Цена и версия не подставляются от себя. Время вступления показывается по правилу GDD 28.
8. Ранее существовавшая карточка сохранена для совместимости с проходящими проверками; строительные материалы и редактирование предприятия остаются доступными в «Кратко».

## Риски и открытые контракты для директора
- Добавить серверные границы цены в GET sales-policy и при необходимости ограничения/остатки/три вклада рейтинга. Пока этого нет, изменение политики справедливо заблокировано.
- Клиент не добавляет premium-подписку и не показывает чужие цены или рейтинги магазинов.
- Проверять совместимость `/enterprises/{id}/supply` после параллельных серверных веток; схема `inputs` взята из текущего main.

## Проверки
Локальный Godot **4.7.2.stable.official.ed1daf0bf**, тот же бинарник установлен на VPS по `/opt/game-tools/godot/4.7.2-stable/`. Выполнены `--editor --quit`, `python3 tools/build_strings.py --check`, `python3 -m unittest tools.tests.test_strings -v`, все 28 Godot smoke из workflow (27 прежних + 1 новый), все layout-проверки четырёх и пяти разрешений, валидация 64 моделей и тесты генератора моделей. Каждый запуск Godot выполнялся с `timeout 90`.

Первый полный проход: **76 команд, 74 успешных, 2 остановлены таймаутом 124 после ошибки assert**, 126 скриншотов.
- `chain2_smoke` падал на строке 53 из-за скрытых материалов стройки в режиме «Кратко»; исправлено без изменения исходного теста, повтор `timeout 25 Godot --headless --path client -s tests/chain2_smoke.gd` прошёл (`chain2 smoke OK`).
- `world_stream_smoke` упал на исходной строке 77 (`assert(growth_events==1)`); код `client/world/stream.gd` и `client/tests/world_stream_smoke.gd` не изменён этой веткой, событие в моке использует старую версию 17 при сохранённом курсоре. Повторный запуск с изолированным `XDG_DATA_HOME=/tmp/lunex-ui-impl1-clean-data` завершился успешно (`world stream smoke OK`), то есть первоначальный отказ вызван старым кэшем Godot, а не изменениями клиента.
- Новый `ui_impl1_smoke` повторно прошёл: режимы, dry-run, idempotency, 403/404/409, выбор поставщиков, рейтинг, PUT магазина, wide layout.

Скриншоты первого локального прогона лежат **только** в рабочем временном каталоге VPS `/tmp/lunex-ui-impl1-screens` (126 PNG).
