# MAP-RT1: карта в реальном времени, этап 1

Статус: **частичная реализация, не принимать до устранения ограничений**.

## Допущения

1. Существующий WSGI-диспетчер держит `pool.connection()` и транзакцию на всём `registry.dispatch`. Поэтому `wait_ms` разбирается и ограничивается, но фактическое ожидание **не реализовано**: спать внутри `world.api.events` опасно. Флаг `world_events_wait_enabled` остаётся выключенным. Для настоящего pool-free long poll нужна отдельная задача на `server/game_server.py` (в текущей зоне строго запрещён), `channel_timeout` 35 и настройки nginx.
2. Очистка журнала **не реализована** и выключена по умолчанию. Нужна проверка reset и миграция старых клиентов до включения.
3. Нет отдельных токенов или конфигурации ожидания на клиенте, используется 2-секундный короткий опрос.
4. Для старого события без объекта используется ETag. Для `city_growth` существующее восстановление радиуса и чанков сохраняется.
5. Журнал нельзя обрезать до миграции всех клиентов, понимающих `reset`.

## Реализовано в разрешённой зоне

- Индекс связи событий и чанков в той же транзакции, новая идемпотентная миграция, без backfill старого журнала.
- Существующий `kind` сохранён; для событий предприятий объект и клетки берутся из `enterprises`, при сносе из удалённых клеток и строки предприятия; дорожные события до 48 клеток.
- Ответ журнала дополняется `event_id`, `type`, `chunks`, `object`, `tip`, `reset`, `scanned`, есть ограничение страницы, фильтрация по чанкам и защита от некорректных координат.
- Защита короткого опроса от чрезмерных запросов (в памяти процесса, требует распределённого лимитера при нескольких worker-процессах).
- Клиент: 2-секундный опрос только при открытой карте, точечная обработка зданий и дорожных клеток, fallback по ETag, снимок при reset/большом отставании.
- Тест `world_realtime_smoke.gd` добавлен в Client checks, старые тесты не изменены.

## Ограничения приёмки

- Тестовый PostgreSQL 16 и 50/100 одновременных слушателей: **не подтверждены на текущем этапе**.
- Полноценный long poll с 12 ожидающими и гарантией p95 ≤ 2 с: **не подтверждён**.
- Унаследованный `world_stream_smoke` бывает нестабилен на нагруженном VPS (счётчик 304 за 6 кадров); нельзя считать CI зелёным без GitHub run.
- `next_after` по фильтру показывает scanned, а не последнее отданное событие. Старые клиенты без chunks совместимы.

## Безопасность

Боевые серверы, базы и сервисы не изменялись. Ветка не сливается в `main`; администраторские флаги не включались. Секреты и личные данные в журнал не добавляются.
