# 04. Промпты, мастер нового проекта, протокол для ИИ

## Мастер-промпт для ИИ-директора [v1, главная страница]
На главной странице портала (список проектов) всегда доступен блок **«Мастер-промпт для ИИ-директора»**: текст, который владелец один раз вставляет новому ИИ-директору, чтобы тот научился работать с порталом. Файл `portal/templates/MASTER_PROMPT.md`, маршрут `GET /api/master-prompt`. Содержание: главный принцип (источник правды `docs/work_plan.json`), **порядок работы** (интервью → репозиторий → GDD → план → слияние и синхронизация → выдача задач владельцем → приёмка → новые функции через план), **структура репозитория** (дерево папок), схема плана, команды `tools/work_plan.py`, обязательные правила, что сделать прямо сейчас. Кнопки: «Скопировать», «Поделиться» (на телефоне), «Показать текст», «Скачать скелет репозитория» (`GET /api/skeleton.zip`, универсальная заготовка без привязки к проекту). Отличие от стартовых промптов проекта: мастер-промпт общий для любого проекта и учит работе с порталом, а стартовые промпты относятся к конкретному проекту (организация репозитория и GDD).

## Генерация промптов задач [v1]
Промпт не пишется руками: `tools/work_plan.py prompt <id>` собирает его из плана: заголовок и линия, цель, правила (один большой заход; репозиторий, ветка по шаблону `branch_pattern`; проект и контракты; зона файлов; общие файлы не менять; секреты запрещены; новые функции за выключенным флагом), проверки линии (`lanes.<л>.checks`), критерии готовности, формат сдачи. Источники правды: `project`, `rules`, `lanes`, пакет. Промпты не привязаны к конкретному проекту.

## Мастер нового проекта [v1]
Поля: название, адрес (slug), репозиторий (необязательно), описание. Результат: запись проекта, **скелет репозитория** (zip), два стартовых промпта.
**Скелет:** `README.md`, `docs/AI_RULES.md`, `docs/PORTAL_PROTOCOL.md`, `docs/DIRECTOR_HANDOVER.md`, `docs/work_plan.json` (стартовый, две линии, два пакета), `docs/WORK_PLAN.md`, `docs/gdd/DECISIONS_APPROVED.md`, `docs/gdd/01_OVERVIEW.md`, `docs/PROGRESS.md`, `tools/work_plan.py`, `.github/workflows/checks.yml`.
**Промпт 1 «Организовать репозиторий и правила»:** роль директора, распаковать скелет, прочитать правила, спроектировать вместе с владельцем, разбить на этапы и линии, проверять план, принимать работу, запреты.
**Промпт 2 «Разработать полный GDD»:** интервью с владельцем; `00_OVERVIEW`; документы модулей с обязательными разделами (цель, данные, формулы целыми числами, состояния, взаимодействие, интерфейс, сервер, безопасность, критерии приёмки, допущения, решения владельца); макеты; симуляции с эталонами и тестами; риски и вопросы; перенос в `work_plan.json` по протоколу.

## Протокол для ИИ [v1]
`portal/templates/PORTAL_PROTOCOL.md` попадает в скелет каждого проекта как `docs/PORTAL_PROTOCOL.md`. Содержание: когда добавлять пакеты в план (при каждой новой функции), схема плана, правила линий и шагов, как писать цель и критерии, что делать после приёмки (`set <id> done`), запреты (секреты, действия на серверах только по команде владельца). Портал показывает протокол кнопкой «Протокол для ИИ».

## Библиотека промптов [v2]
Общие промпты для разовых задач: «принять работу исполнителя» (проверки), «исправить замечания», «обновить README и дорожную карту», «подготовить релиз» (только по команде владельца), «провести аудит безопасности». Хранятся (планируется) в `portal/templates/prompts/`, подставляют данные проекта.

## Типы проектов [v3]
Шаблоны скелета: «игра», «веб-сервис», «мобильное приложение», «данные и исследования»; различаются линиями, зонами и проверками.

## Версионирование промптов [v2]
Каждый выданный промпт запоминается (хеш и дата), чтобы видеть, что исполнитель получил; при изменении плана портал предлагает выдать обновление.
