# 10. Дорожная карта, критерии приёмки, риски

## Дорожная карта
| Версия | Содержание | Статус |
|---|---|---|
| v1 | вход, проекты, мастер, план, доска GTD, панель задачи, идеи, справка, подсказки, тёмная тема, протокол, развёртывание (инструкция) | реализовано в коде, не выкачено на VPS |
| v1.1 | развёртывание на rikagro.ru/createportal, резервные копии, проверка в бою | ждёт команды владельца |
| v2.0 | настройки, журнал аудита, смена пароля, сброс сеансов | проект |
| v2.1 | вебхук GitHub, PR и CI на задаче, автоотметка слияния, уведомления | проект |
| v2.2 | отчёты, чек-листы приёмки, доработка, метрики, граф зависимостей, библиотека промптов | проект |
| v3 | роли и несколько пользователей, комментарии, типы проектов, реестр исполнителей, экспорт и импорт, поиск | идея |

## Критерии приёмки v1 (выполнены)
- Вход только по паролю, лимит попыток, CSRF, CSP; тесты на каждую меру.
- Создание проекта выдаёт два промпта и скелет репозитория, который проходит проверку плана.
- Загруженный план проходит валидатор; ошибки возвращаются списком.
- Нельзя выдать задачу, пока предыдущие не приняты; статусы и даты сохраняются.
- Данные проектов не смешиваются; идеи и состояния отдельные.
- Интерфейс работает на компьютере и телефоне, в светлой и тёмной теме, без ошибок консоли.
- 19 автотестов проходят; промпты не привязаны к конкретному проекту.

## Критерии приёмки v2
- Вебхук принимает только подписанные запросы, повтор доставки безопасен, PR связывается с задачей по ветке или `id`.
- Статус CI виден на задаче; приёмка недоступна при красном CI без явной пометки владельца.
- Уведомления приходят по включённым событиям и не чаще одного в час на событие.
- Чек-лист приёмки сохраняется, метрики считаются верно на тестовых данных.
- Резервная копия создаётся из интерфейса и восстанавливается на тесте.
- Все новые маршруты покрыты тестами, нет утечки секретов в ответах и журналах.

## Риски
| Риск | Мера |
|---|---|
| Единая точка отказа (один сервис, SQLite) | ежедневные копии, проверка восстановления, простой откат |
| Устаревший план (директор забыл обновить) | вебхук `push`, пометка «план не обновлялся N суток», протокол обязывает обновлять |
| Расхождение инструмента плана в портале и в проектах | копия `tools/work_plan.py` в шаблоне сверяется тестом, версия схемы в плане |
| Утечка токена GitHub | токен только на чтение, файл 0600, ротация по инструкции, портал не показывает его |
| Сложность вебхуков и публичного маршрута | подпись, лимит размера, идемпотентность, отдельный секрет |
| Рост числа проектов | пагинация списка, поиск, архивация проектов |
| Неправильная приёмка (владелец нажал по ошибке) | двойное нажатие, возврат из архива, журнал |
