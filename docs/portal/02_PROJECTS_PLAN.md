# 02. Проекты и план работ

## Проект [v1]
`slug` (латиница, цифры, дефис, 3–40 знаков), `name`, `repo` (`владелец/имя`, необязательно), `description`, дата создания. План хранится снимком JSON с датой последней загрузки. Удаление проекта [v2]: только владелец, с подтверждением набором slug.

## Схема `docs/work_plan.json`
Файл ведёт ИИ-директор в репозитории проекта (протокол: [04](04_PROMPTS_WIZARD.md)). Поля верхнего уровня: `project` {name, repo, branch}, `rules` {shared_files_director_only[], branch_pattern, merge}, `lanes` {A,B,...}: {name, who, zone[], note, checks[]}, `packages[]`.
**Пакет:** `id` (буква линии + число), `title`, `lane`, `step` (1,2,3...), `depends_on[]`, `gdd[]` (номера документов), `goal`, `done_when[]`, `zone_extra[]`, `status` (`planned|wip|done`), `size` (S/M/L).

## Правила и проверки (валидатор `tools/work_plan.py`)
1. `id` уникальны; зависимости существуют.
2. Зависимость должна быть на более раннем шаге (или на пакет своей линии выше по шагу).
3. На каждом шаге не более одного пакета на линию.
4. Пакеты разных линий одного шага не зависят друг от друга и не пересекаются по зонам файлов (проверка по префиксам; исключение: `docs/qa/` с именами по `id`).
5. Зоны линий не пересекаются с общими файлами директора.
6. Нет циклов; у пакета есть цель и критерии.
Портал принимает план только после проверки; при ошибках возвращает список (до 20) и план не меняется.

## Линии
Минимум две линии работают одновременно и независимо (для игры: A сервер и B клиент). Линия определяется зоной файлов и исполнителем. Клиентская линия работает по контракту через заглушки, поэтому не ждёт серверную.

## Получение плана
- **Загрузка вручную** [v1]: вставка JSON.
- **Синхронизация по кнопке** [v1]: чтение `docs/work_plan.json` из репозитория через GitHub API (токен только на чтение, необязательный для публичных репозиториев).
- **Автосинхронизация** [v2]: вебхук GitHub на событие `push` в `main`, обновление плана за секунды; при ошибке плана портал оставляет прежний и уведомляет владельца.

## Изменение плана во время работы
При обновлении плана состояния задач сохраняются по `id`. Если пакет удалён из плана, его состояние остаётся в архиве с пометкой «удалён из плана». Если изменилась цель или критерии у выданной задачи, портал показывает пометку «план изменён после выдачи» и предлагает скопировать промпт заново.
