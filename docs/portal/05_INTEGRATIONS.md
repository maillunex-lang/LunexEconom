# 05. Интеграции и уведомления

## GitHub [v1: чтение плана]
Чтение `docs/work_plan.json` через `GET /repos/{repo}/contents/docs/work_plan.json` (формат raw). Токен fine-grained только на чтение содержимого (Contents: Read), хранится в файле на сервере; для публичного репозитория не нужен. Ограничения: таймаут 15 секунд, размер до 1 МБ, репозиторий проверяется по маске `владелец/имя`.

## Вебхуки GitHub [v2]
Адрес `/createportal/hook/github` (публичный маршрут, без сессии), подпись `X-Hub-Signature-256` проверяется секретом из файла на сервере; события: `push` в `main` (обновить план), `pull_request` (статус PR, слияние), `check_suite` и `workflow_run` (результат CI). Неподписанные запросы отклоняются 401; повтор доставки безопасен (идемпотентность по `X-GitHub-Delivery`).
**Связь PR с задачей:** по имени ветки `v2/<id>-...` или по `id` в заголовке PR. Портал показывает на задаче PR, SHA, статус проверок и «слито» без участия владельца.
**Автоприёмка (решение владельца 2026-11-16):** задача закрывается как «Принято» сама, когда выполнены все условия:
1. задача связана с PR (по ветке `<префикс>/<id>-...` или `id` в заголовке);
2. PR **слит в основную ветку проекта** (`project.branch`, по умолчанию `main`);
3. на слитом коммите в основной ветке **все проверки CI успешны** (`workflow_run` и `check_suite` для SHA слияния; нужное число проверок задаётся в настройках проекта, по умолчанию: все, что запущены на этом SHA, и их не меньше одной);
4. задача сейчас в статусе `issued` или `submitted` (если задачу забыли отметить выданной, она тоже закрывается с пометкой «без отметки выдачи»).
Почему это безопасно: исполнители не сливают в `main`, сливает только директор после своей проверки (пробное слияние, тесты, зона файлов), поэтому слияние и есть решение о приёмке. Если CI на основной ветке красный или проверки ещё идут, задача остаётся в «Ждёт приёмки» с пометкой «ждём CI»; при падении CI приходит уведомление и автоприёмка не срабатывает. Ошибочное закрытие отменяется кнопкой «Вернуть из архива». Настройки проекта: `auto_accept` (включено по умолчанию), `auto_accept_require_checklist` (выключено: слияние директором уже есть проверка). Каждое автозакрытие пишется в журнал событий и в уведомление («A2 принято автоматически: слито в main, CI зелёный, SHA abc1234»).

## Уведомления [v2]
**Решение владельца (2026-11-16):** уведомления нужны; каналы: **MAX** (российский мессенджер) и/или **Telegram**. Портал строится на общем интерфейсе «канал уведомлений» с адаптерами, поэтому подключается любой из каналов и они могут работать одновременно; почта остаётся необязательным третьим каналом.

**Адаптеры:**
| Канал | Как отправляем | Что нужно от владельца |
|---|---|---|
| MAX | HTTPS-запрос к API ботов MAX (`POST /messages`, токен бота в заголовке `Authorization`); получение событий для привязки: webhook-подписка (`POST /subscriptions`) или long polling (`GET /updates`) | профиль самозанятого (или ИП/организации) на платформе MAX для партнёров, верификация, создание бота, модерация бота; токен кладётся на сервер самим владельцем |
| Telegram | Bot API (`sendMessage`), создание бота через @BotFather за минуту, без верификации | токен бота; доступность Telegram с сервера в России может быть нестабильной, проверяется при развёртывании |
| Почта | SMTP, по желанию | параметры почтового ящика в файле на сервере |

**Привязка владельца (без ввода идентификаторов вручную):** в настройках портал показывает одноразовый код на 10 минут; владелец отправляет этот код своему боту; портал получает сообщение (подписка или long polling), проверяет код и запоминает идентификатор чата владельца. Бот отвечает «подключено». Идентификатор чужого человека сохранить нельзя: принимается только сообщение с действующим кодом. Отвязка кнопкой «Отключить».

**События:** исполнитель сдал (по вебхуку PR), CI упал на PR выданной задачи, задача ждёт приёмки больше суток, план обновлён с ошибкой, вход с нового устройства, не создана резервная копия. Настройки включают и выключают каждое событие по каждому каналу. Защита от шума: не чаще одного уведомления на событие в час, при недоставке повтор через 5 минут не более трёх раз, затем запись в журнал.

**Содержание сообщения:** короткий текст и ссылка на портал: «Башкирия: A1 сдано, ждёт приёмки. https://rikagro.ru/createportal/». Секреты, промпты и тексты отчётов в сообщения не включаются.

**Безопасность:** токены ботов лежат в файлах на сервере с правами 0600 вне репозитория и базы; портал показывает только «подключён/нет»; исходящие запросы только к известным адресам API (список в коде), с таймаутом 10 секунд; входящие сообщения от ботов обрабатываются только для привязки.

Ссылки на документацию: [платформа MAX для партнёров](https://dev.max.ru/docs), [API ботов MAX](https://dev.max.ru/docs-api). Точные параметры методов MAX (получатель и формат сообщения) подтверждаются по актуальной документации при реализации.

## Исполнитель без API
Исполнители (ChatGPT, Grok, Perplexity, Copilot) не имеют API в портале: владелец сам копирует промпт и отчёт. Портал не хранит ключи ИИ и не вызывает ИИ [v1, v2]. [v3]: необязательный помощник, который сам составляет текст сообщения директору из состояния проекта (через ключ владельца, по желанию).

## Экспорт и импорт [v3]
Выгрузка проекта в JSON (план, состояния, идеи, события) и загрузка на другой портал.
