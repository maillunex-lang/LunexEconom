# 09. Развёртывание и эксплуатация

Развёртывание выполняется **только по прямой команде владельца** (Часть C) через исполнителя с доступом к VPS. Подробная инструкция: [`portal/DEPLOY.md`](../../portal/DEPLOY.md).

## Состав
Один процесс Python 3.12 (стандартная библиотека), SQLite (WAL), слушает 127.0.0.1:18790, наружу nginx по HTTPS `rikagro.ru/createportal/`. Пользователь `createportal` без входа, каталоги `/opt/createportal` (код, только чтение) и `/var/lib/createportal` (данные, 0700). systemd: `NoNewPrivileges`, `PrivateTmp`, `ProtectSystem=strict`, `ProtectHome`, `UMask=0077`. Игра и её база не затрагиваются.

## Резервные копии
Ежедневно `sqlite3 ... ".backup"` в `/var/backups/createportal/`, 14 копий, копия на второй диск раз в неделю; раз в неделю проверка восстановления на временной копии с отчётом. [v2]: кнопки «Создать копию сейчас», «Скачать последнюю» (под входом владельца), статус копий в настройках.

## Обновление
Копирование нового `portal/` и `tools/work_plan.py` из `main` в `/opt/createportal`, предыдущая версия в `/opt/createportal.prev`, перезапуск, проверка `/health`. Схема БД обновляется сама при старте. Откат: вернуть `.prev` и базу из копии.

## Мониторинг [v2]
`/health` проверяет также доступ к базе; метрики процесса (число запросов, ошибки 5xx) в журнале; алерты владельцу: сервис недоступен, диск меньше 15 %, копия не создана больше суток. Журнал сервиса через `journalctl`, без секретов.

## Безопасность эксплуатации
Пароль задаётся владельцем на сервере; токены GitHub и уведомлений в файлах 0600; вебхуки подписаны; nginx ограничивает вход и размер запроса; HTTPS обязателен (cookie Secure); доступ к серверу только по команде владельца.

## Производительность
Расчёт на одного владельца и десятки проектов: сотни пакетов на проект; ответы до 100 мс; план и промпты собираются на лету (кеш по хешу плана [v2]).
