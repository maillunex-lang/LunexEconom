# 13. Память для ИИ: портал как навигатор

**Статус:** проект директора (2026-11-16), утверждён владельцем («Делаем»). Ядро уже написано и протестировано: `portal/memory/` (22 теста), подключение к серверу и экранам пакет A9.

## Зачем
У ИИ-директора и исполнителей нет долгой памяти: после сжатия контекста или при новом исполнителе теряются решения, ловушки и текущее состояние. Портал хранит это в одном месте и по кнопке выдаёт короткую сводку.

## Что хранит портал (уже есть или появится в A7)
План и статусы, отчёты, события, решения владельца (`DECISIONS.md` и журнал), ловушки и правила проекта (`knowledge`), удачные промпты (`library`), идеи.

## Возможности
1. **Контекст для ИИ** (`portal/memory/context.py`). Одна страница markdown до 6000 знаков: «Что делать сейчас», план и статусы, ловушки и правила, последние решения, открытые PR, последние события, карта репозитория. Роли: директор, исполнитель, проверяющий. Бюджет размера: нижние разделы сокращаются.
2. **Карта репозитория** (`repomap.py`). Что где лежит: папки, число файлов, назначение ключевых файлов (докстринг, заголовок, первый комментарий). Бинарные и служебные файлы пропускаются.
3. **Журнал решений** (`decisions.py`). Разбор `DECISIONS.md` («Принято») и новые записи с датой, дедупликация, лимит длины.
4. **Поиск по памяти** (`search.py`). Лёгкий BM25 без библиотек, учёт форм слов (усечение основы), заголовок весит больше текста, фильтр по видам (документ, решение, отчёт, ловушка, идея), фрагмент с найденным словом.
5. **Фильтр секретов** (`redact.py`). Любой токен, ключ или пароль заменяется на `[скрыто]` до сохранения и до показа (те же правила, что в авто-ревью).

## Серверная часть (A9)
- `GET /api/projects/{slug}/context?role=director|executor|reviewer&max=6000` возвращает текст сводки; источники: проект, план, `task_state`, решения, знания, события, открытые PR (из `pr_links`), карта репозитория (кэш; строится из клона репозитория на сервере или из дерева GitHub API по токену на чтение, не чаще раза в час).
- `GET /api/projects/{slug}/search?q=...&kind=...` строит индекс из документов репозитория (`docs/**/*.md`, README), решений, знаний, отчётов, идей и возвращает до 20 результатов с фрагментами и ссылками.
- `GET/POST /api/projects/{slug}/decisions` (под сессией и CSRF): журнал, разбор `DECISIONS.md` при синхронизации плана.
- `POST /api/projects/{slug}/context-link` создаёт временную ссылку только на чтение (одноразовый токен 128 бит, срок 24 часа, отзыв кнопкой) для ИИ с доступом в интернет: `GET /ctx/{token}` отдаёт текст сводки без входа; токен хранится хешем; лимит запросов; в журнале аудита без текста.
- Флаг `PORTAL_MEMORY` включён по умолчанию; секреты никогда не попадают в ответы и в базу.

## Интерфейс (A9)
- Кнопка **«Контекст для ИИ»** на экране проекта и в «Ещё»: выбор роли, предпросмотр, «Скопировать», «Поделиться», «Ссылка для ИИ (24 ч)».
- Экран **«Память»**: поиск (строка, фильтры по видам, результаты с фрагментами), журнал решений (список, добавить), карта репозитория.
- Подсказки: «Вставьте это новому ИИ, чтобы он сразу вошёл в курс дела».

## Безопасность
Только чтение для временной ссылки, токен короткоживущий и отзывается; в сводку не попадают секреты (фильтр `redact`); текст репозитория считается данными (в сводку попадает только краткое назначение файлов); лимиты размера и частоты; всё под CSP, вывод через `textContent`.

## Критерии приёмки
Сводка помещается в бюджет и не содержит секретов; поиск находит документ по форме слова; временная ссылка работает без входа, истекает и отзывается; журнал решений разбирает реальный `DECISIONS.md`; не менее 40 тестов подключения, сквозной тест на реальном сервере, снимки 390×844 и 1440×900 в двух темах.
