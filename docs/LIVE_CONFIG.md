# Live Config и обновления данных без переустановки APK

**Ветка:** ChatGPT13. Статус: разработка, в production не развернуто.

## Область применения
Облако доставляет серверные флаги и параметры (сервер авторитетен), клиентские флаги отображения, строки, PNG/WebP и GLB 2.0. GDScript и другие исполняемые изменения не доставляются: для них нужна новая APK.

## Ревизии
`runtime_config_values` хранит значения и месяц применения, `runtime_config_revisions` полные снимки, автора и комментарий, `runtime_config_state` ревизию, `adm_audit` действия. Слои: код → окружение → база. При пустой базе исходная симуляция не меняется. Применение экономики со следующего месяца; режим обслуживания и клиентские флаги сразу после публикации. Откат создаёт новую ревизию.

## Канонические подписи
Публичный GET /config возвращает `schema:1`, `revision`, `payload_b64` (base64 исходных UTF-8 байтов JSON) и `signature` (base64 подписи RSA-PKCS#1 v1.5 SHA-256). JSON формируется Python с `sort_keys=True`, `separators=(',', ':')`, `ensure_ascii=False`. Внутренний payload содержит `schema`, `revision`, `flags`, `parameters`, `texts`, `min_version`, `recommended_version`, `patch_manifest_url`, `maintenance`. Приватный ключ не помещается в репозиторий.

До подписания первого снимка GET /config отвечает 503. Сервер сохраняет последний подписанный снимок, даже если новые настройки ещё ожидают подписи. Изменения серверных флагов независимы от публичного снимка. Сервер проверяет публикацию по пути `LUNEX_LIVE_CONFIG_PUBLIC_KEY`, который должен указывать на тот же открытый PEM, что и `client/livepatch_public.pem`.

## Безопасная публикация
Сохранить настройки в студии, получить кандидат `GET /admin/config/candidate`, затем из доверенной root-сессии запустить:

```bash
cd admin_studio
python3 sign_config.py --studio http://127.0.0.1:18991 --key /etc/lunexeconom/livepatch-private/signing-private.pem
```

Токен World Studio передаётся только как переменная окружения `LUNEX_ADMIN_TOKEN`, не в CLI. Скрипт подписывает точные байты, отправляет только подпись и ожидаемую ревизию в защищённый `POST /admin/config/sign`. Ключ не доступен веб-процессу. Ревизии с недействительной подписью отклоняются.

## Android
`client/live_config.gd` запрашивает настройки при запуске, каждые 10 минут и при возвращении из фона. Сначала проверяет подпись с публичным ключом внутри APK, только потом принимает JSON. Проверенный кеш хранится в `user://live_config/config.json` и проверяется заново при загрузке. Неизвестные поля не ломают клиент. При сетевой ошибке работает последняя проверенная конфигурация.

Кнопка «Проверить обновление» проверяет конфигурацию, подписанный LivePatch (изображения и GLB) и манифест APK. Только исполняемое обновление требует установки новой APK. Каждый ресурс LivePatch ограничен размером, длиной, форматом, SHA-256, а весь манифест проверяется подписью. GLB загружается из `user://` через `GLTFDocument` после проверки, без исполнения скриптов.

## Границы текущей реализации
Подписание остаётся ручным этапом для защиты приватного ключа. Не все константы `economy.py` имеют живые потребители `balance.get` и не становятся управляемыми автоматически. Привязка фона штаба зависит от параллельной ветки ChatGPT10. Источник возраста резервной копии пока не предоставляется `ops/health_monitor.py` (тот проверяет только доступность сервиса). Это нужно завершить перед production.
