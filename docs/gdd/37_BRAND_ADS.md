# GDD 37. Бренд и реклама

**Статус:** проект директора (2026-11-16), **balance: draft**. Макет `docs/mockups/caplab_advertising_1920x1080.svg` (GDD 30). Симулятор `tools/sim/wave4/` (раздел brand), тесты `tools/tests/test_wave4_sim.py`. Волна 4.

## 1. Модель
У компании по каждому товару есть **известность бренда** `brand_bp` (0..10000). Реклама её повышает с убывающей отдачей, она естественно затухает. Бренд даёт вклад в рейтинг товара (GDD 06: рейтинг = цена + качество + бренд, вес бренда по товару, у еды ниже, у одежды и техники выше).
```
gain_bp  = budget_rub * 8 // 1000 * (10000 - brand_bp) // 10000
decay_bp = brand_bp * 300 // 10000                      # 3 % в месяц
brand_bp = clamp(brand_bp + gain_bp - decay_bp, 0, 10000)
rating_points = brand_bp * rating_weight_bp // 10000 * 100 // 10000
```
Вес бренда в рейтинге 25 % (по умолчанию, параметр товара). Каналы: местная пресса, радио, интернет, билборды; у каждого цена в месяц и охват в % населения города, итоговый множитель к gain зависит от охвата. Реклама платится через ledger (`system:media`), при нехватке денег месяц пропускается.

## 2. Симуляция (24 месяца, выручка 800 000 ₽/мес, маржа 25 %)
| Бюджет в месяц | Бренд в конце | Прибыль за 24 мес., ₽ |
|---|---|---|
| 0 | 0 % | 4 800 000 |
| 30 000 | 32,7 % | 5 097 000 |
| 90 000 | 65,3 % | 5 052 000 |
Вывод: умеренный бюджет окупается (+6 %), чрезмерный даёт убывающую отдачу и убыток против умеренного. Игроку это показывается в экране рекламы как «оптимальный бюджет примерно N ₽».

## 3. Серверная часть и решения
Таблицы `brand_state(company_id, product_id, brand_bp)`, `ad_campaigns(company_id, channel, budget, active)`, месячный тик бренда после розницы. Маршруты `GET/PUT /advertising`, `GET /brand/{product}`. Флаг `advertising_enabled` выключен по умолчанию. Конкурентам бренд виден публично только как «известность: низкая/средняя/высокая». Решение владельца: цены каналов и охват через админку A3 (рекомендация).
