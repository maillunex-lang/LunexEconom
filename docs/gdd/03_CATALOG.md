# GDD 03. Каталог данных

**Цель:** единый источник правды о товарах, рецептах, зданиях и специализациях. Хранится в `server/data/*.json`, проверяется схемой при запуске и в CI, версионируется, отдаётся клиенту через API. Параллельных каталогов нет.

## Товар (`goods.json`)
`id`, `name`, `unit`, `category` (сырьё, полуфабрикат, потребительский, промышленный), `reference_price` (игровой ₽), `vat_category`, `consumer` (покупают жители), `base_demand_per_capita` (в день на 1000 жителей), `elasticity` (цена), `rating_weights` {brand, quality, price} (сумма 1; для каждого товара свои), `quality_range` (1–100), `obsolescence` (необязательно).
Стартовый набор для M1: мёд, зерно, мука, хлеб, молоко, мясо, овощи, нефть, газ, песок, лес, камень, цемент, сталь, одежда, ткань, электроника, топливо (≈ 25 товаров, реальные цены Башкортостана).

## Тип предприятия (`buildings.json`)
`id`, `name`, `role` (добыча, ферма, завод, склад, магазин, офис, жильё, медиа), `size` (клетки), `build_cost`, `build_months`, `upkeep_month`, `jobs`, `storage_capacity`, `zones` (где можно), `deposit` (необязательно), `levels` (необязательно).

## Рецепт (`recipes.json`)
`building`, `outputs` {товар: объём в игровой день при полной загрузке}, `inputs` {товар: объём в день}, `quality_model` (как качество выпуска зависит от качества сырья, уровня технологии и обучения), `workers`.

## Специализации магазинов (`retail.json`)
`id`, `name`, `allowed_goods`, `cells` (4, 9, 12–16), `traffic_weight`, `appeal` (базовая привлекательность). Первая версия: 8–10 (продуктовый, супермаркет, хлебный, одежда, электроника, мебель, аптека, стройматериалы, автозапчасти).

## Версии и API
Файл версии (`catalog_version`), `GET /catalog` (весь каталог), `GET /catalog/goods`, `/catalog/buildings`, `/catalog/recipes`, `/catalog/retail` с кешем. Проверка схемы и инвариантов при старте: у входа есть производитель, нет циклов, у товара есть покупатель, суммы весов рейтинга равны 1, размеры совместимы с картой.

## Приёмка
Невалидный каталог не стартует; тест инвариантов на цепочки; клиент получает каталог одним запросом; замена файла и перезапуск меняют игру без правки кода.
