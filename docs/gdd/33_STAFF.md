## 1. Модель
Рабочие места здания делятся на группы (рабочие, операторы, логисты, технологи; набор зависит от типа здания). У группы есть **уровень 1–9**. Сейчас в игре только единая зарплата за рабочее место (100 ₽ в месяц на место по текущему черновику); новая модель вводится за флагом `staff_levels_enabled` (по умолчанию выключен, поведение прежнее).
```
productivity_bp = 8000 + 500 * (level - 1)                     # 80 %..120 %
expected_wage   = base_wage * (10000 + 1200 * (level - 1)) // 10000
level_up_cost   = 600 * level * level                           # очки обучения
points_month    = training_budget * 250 // 1000
```
Выпуск = рабочие × выработка на рабочего × productivity × настроение / 10000, ограничен спросом и вместимостью.

## 2. Зарплата и текучесть
Игрок задаёт зарплату группы. Ниже ожидаемой (по уровню) растут текучесть и падает настроение:
```
under        = (expected - wage) * 10000 // expected
turnover_bp  = max(50, 150 + under * 120 // 1000)             # в месяц
morale_bp    = max(6000, 10000 - under * 6000 // 10000)
```
Уволившихся заменяют новичками уровня 1 (стоимость найма 1 месячная зарплата); средний уровень группы падает пропорционально доле ушедших. Зарплата выше ожидаемой снижает текучесть только до пола (50 б.п.), производительность не растёт.

## 3. Обучение
Бюджет обучения в месяц превращается в очки; когда накоплено `level_up_cost`, уровень группы растёт на 1. Интенсивный курс: расход ×2, очки ×1,5 (параметр). Обучение платится через ledger (`system:training`); при нехватке денег месяц пропускается.

## 4. Найм
Список кандидатов (3–5) обновляется раз в игровую неделю по городу: имя, уровень, запрашиваемая зарплата (`expected_wage ± 10 %`). Найм платный (1 месячная зарплата), нанятый встаёт в группу. Число рабочих мест ограничено зданием. Для зданий с флагом выключенным найм автоматический по прежней схеме.

## 5. Симуляция (24 месяца, 25 рабочих, спрос ≤ 8000/мес)
| Сценарий | Итоговый уровень | Увольнений | Прибыль, ₽ |
|---|---|---|---|
| Рыночная зарплата, без обучения | 1 | 9 | 2 256 204 |
| Низкая зарплата (70 %) | 1 | 30 | 1 849 548 |
| Рыночная + обучение 20 000 ₽/мес | 8 | 9 | 1 855 272 |
| Высокая зарплата (130 %) + обучение | 8 | 9 | 1 218 475 |
Выводы: низкая зарплата не окупается (в 3 раза больше увольнений и слабее настроение); обучение за 24 месяца только выходит в ноль, потому что выпуск упирается в спрос, а зарплата растёт вместе с уровнем (для предприятий с неограниченным спросом или дорогим товаром оно окупится). Переплата не даёт выгоды. Параметры `draft`, пересматриваются в полном балансе.

## 6. Серверная часть (план)
`staff_groups(enterprise_id, group_id, level, workers, wage, version)`, `training_state`, `candidates(city_id, week, ...)`, `staff_events`. Маршруты: `GET/PUT /enterprises/{id}/staff`, `POST /enterprises/{id}/staff/hire`, `PUT /enterprises/{id}/staff/training`. Месячный тик персонала перед производством. Тесты: уровни, текучесть, нехватка денег, идемпотентность, флаг выключен.
