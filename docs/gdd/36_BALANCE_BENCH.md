# GDD 36. Стенд баланса и методика пересмотра цен

**Статус:** инструмент и методика готовы (2026-11-16), числа каталога остаются `draft` (D-93). Инструмент `tools/balance/bench.py`, тесты `tools/tests/test_balance_bench.py`. Основа для полного пересмотра баланса в Волне 3.

## 1. Зачем
До сих пор окупаемость считалась вручную и только для хлебной цепочки (`python -m tools.sim balance`). Теперь есть общий стенд: он читает каталог (`server/data` или любой каталог из предложения) и за секунды показывает окупаемость каждого рецепта и здания, помечая перекосы. Предложения по ценам (Perplexity, исполнители, мои) проверяются им до внесения.

## 2. Запуск
```
python -m tools.balance.bench                                # текущий каталог
python -m tools.balance.bench --catalog <папка> --json out.json   # любой каталог с products/buildings/recipes.json
python -m tools.balance.bench --wage 2100 --goal-lo 15 --goal-hi 30
```

## 3. Что считается (целые, деление вниз, 30 суток в месяце)
```
добавленная стоимость в сутки = Σ(выход × справочная цена) − Σ(вход × справочная цена)
прибыль в месяц               = добавленная × 30 − рабочие места × зарплата − содержание
окупаемость, суток            = стоимость постройки × 30 // прибыль в месяц
```
Метки: **loss** (убыток), **fast** (окупаемость короче нижней цели, 15 суток, слишком легко), **slow** (длиннее цели × 12), **ok**. Допущения: полная загрузка, спрос не ограничен, весь выпуск продан по справочной цене (то есть это верхняя граница), НДС и налоги не учтены. Для проверки спроса и конкуренции служат симуляторы GDD 27, 28, 35.

## 5. Методика пересмотра (по шагам)
1. Зафиксировать цель окупаемости по классам: сырьё 20–40 суток, переработка 20–30, конечные товары 25–40, розница 30–60 (параметр, решает владелец).
2. Выровнять справочные цены по реальным пропорциям (REAL_PRICES) в рамках масштаба M; потом пересчитать стоимость зданий и содержание под целевую окупаемость.
3. Прогнать стенд, добиться, что нет `loss`, нет `fast` и нет `slow` вне класса.
4. Прогнать симуляторы спроса, поставок и ИИ (GDD 27, 28, 35) на 24 месяца: нет спирали бедности, нет монополии, прибыль ИИ ≤ 120 %.
5. Внести через админку A3 с предпросмотром и откатом поэтапно (сначала одна отрасль на тестовом мире).
6. Включить новый каталог только после проверки на тестовом мире и по команде владельца (мир не стирается без отдельного разрешения).

## 6. Решения для владельца
| Вопрос | Рекомендация |
|---|---|
| Когда делать пересмотр | В Волне 3, после слоёв населения и режимов продажи, но до открытой беты |
| Цели окупаемости по классам | Сырьё 20–40 суток, переработка 20–30, конечные товары 25–40, розница 30–60 (на утверждение) |
| Исправлять ли явный убыток НПЗ сейчас | Да, как минимальную правку через админку, если он мешает тестам; полный пересмотр позже |
