# GDD 42. Нагрузка и надёжность

**Статус:** проект директора (2026-11-16). Требуется для открытой беты. Волна 5.

## 1. Цели
100–300 одновременных игроков на одном VPS на PostgreSQL 16; p95 запросов API ≤ 400 мс; суточный тик ≤ 60 с при 300 игроках; потеря данных при аварии не более 5 минут; откат любого релиза за 15 минут.
## 2. Карта в реальном времени, этап 2 (long poll)
Сейчас HTTP-диспетчер держит соединение с БД всё время запроса, поэтому ожидание событий невозможно. План: (1) разделить пулы соединений на короткие (запросы) и ожидание (без соединения, только подписка в памяти процесса по LISTEN/NOTIFY); (2) `wait_ms` до 20 с, не более 12 ожидающих на аккаунт (GDD 22); (3) очистка журнала событий по сроку 24 часа с `reset` для отставших; (4) нагрузочный тест 50 и 100 слушателей. Реализация отдельным заказом ChatGPT.
## 3. Резервные копии
Ежесуточный `pg_dump` + WAL-архив, хранение 14 дней, копия на второй диск, раз в неделю тест восстановления на временной БД; шифрование копий. Переключение только по команде владельца.
## 4. Миграции и откат
Каждая миграция идемпотентна; перед релизом снимок БД; откат релиза = предыдущий APK/манифест (механика есть) + обратная миграция или восстановление из снимка. Запрет несовместимых миграций между версиями клиента (поле `min_version_code`).
## 5. Мониторинг и алерты
Метрики: время запросов, ошибки 5xx, глубина очереди тика, длительность тика, размер БД, свободное место, число онлайн; алерты в админ-панель и на почту владельца: тик пропущен, ошибка тика, 5xx выше порога, место ниже 15 %. Журнал аудита уже есть (A1–A3).
## 6. Нагрузочный набор
`tools/loadtest/` расширить сценариями: регистрация, вход, карта, стройка, поставки, розница, long poll; пороги в CI nightly (не блокируют PR). Тест хаоса: перезапуск процесса во время тика, повтор тех же request_id.
## 7. Безопасность эксплуатации
Секреты только на сервере в отдельном файле, ротация ключей по инструкции, второй слой лимита входа в nginx, обновление образа PostgreSQL (libxslt) по команде владельца, все действия на VPS только по команде.
