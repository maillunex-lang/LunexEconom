# Бриф для второго Grok (Grok2First): «Башкирия: Мёд и Нефть»

Общий контекст, архитектура, правила двух БД, тесты — в [GROK_BRIEF.md](GROK_BRIEF.md) (читать целиком; **задача про контракты между игроками — не твоя**, её делает первый Grok в ветке `GrokFirst`) и [PARALLEL_WORK.md](PARALLEL_WORK.md).

## Ветка и слияние
- Вся работа **только в ветке `Grok2First`** (от свежего `main`). В `main` не пушить, PR не создавать и не сливать — слияние делает Claude по команде владельца.
- Параллельно работают `GrokFirst` (контракты между игроками) и `GPTFirst` (рейтинг и лента событий). Твоя задача **не меняет игровой код**: только новые файлы в новых каталогах. Менять существующие файлы можно лишь для добавления одной строки в `server-check.yml` (список тестов) и записи в `docs/PROGRESS_GROK2.md`.

## Задача: симулятор баланса и стресс-тест экономики
Цель — найти, где экономика ломается или вырождается, до того как это заметят игроки.

1. **`tools/balance_sim.py`** (новый каталог `tools/`): запускает серверную логику на временной SQLite-базе без HTTP (как это делают тесты — см. `server/test_production.py`, `test_npc.py`, `test_labor.py`) и прогоняет длинные сценарии по месяцам: только NPC; NPC + N «ботов-игроков» с простыми стратегиями (строит по кругу, копит, берёт кредиты, ничего не делает); разные длины месяца. Время — вызовами `production.advance`/`step_month` с подменой часов, не реальным ожиданием.
2. **Метрики по месяцам** (CSV и краткий отчёт Markdown): цены honey/oil/goods, население и безработица, число зданий, деньги игроков/NPC/казны/города, банкротства, налоги, суммарные проводки (**сумма всех проводок = 0**, нет отрицательных запасов, нет отрицательных денег там, где запрещено).
3. **Проверки-инварианты и «красные флаги»:** деньги берутся из воздуха; цена упёрлась в границу на много месяцев; население ушло в 0 или раздулось; все NPC обанкротились; казна города уходит в минус; время месяца > заданного бюджета (производительность: сколько мс занимает шаг при 50/200/1000 зданий).
4. **Тесты** `tools/test_balance_sim.py`: короткий сценарий (24 месяца) с проверкой инвариантов; детерминированность (одинаковый seed → одинаковый результат).
5. **Отчёт** `docs/BALANCE_REPORT.md`: найденные проблемы с воспроизведением (seed, месяц, метрика) и предложения по правкам — **сами игровые константы и код не менять**, только описывать; решение о правках принимает владелец.

## Правила
- Не трогай `server/*.py`, `client/*`, `ops/*`, `web/*`, workflows (кроме одной строки в `server-check.yml`). Если нужен хук в сервере — опиши в отчёте, не правь.
- Работает с SQLite; PostgreSQL-вариант — по желанию отдельной опцией, только на одноразовой базе `lunex_ci`, **никогда на боевой**.
- Стандартная библиотека Python (без новых зависимостей, кроме уже используемых).
- SQLite-соединения закрывать (`sqlite_util`).
- Проверки: `cd server && python -W ignore -m unittest discover -p 'test_*.py'`, `cd ../tools && python -m unittest discover -p 'test_*.py'`. Ничего не помечай «готово» без реально запущенных тестов.
- Периодически `git rebase origin/main`.
