## Твоя работа

1. Подготовь отдельную ветку в репозитории и распакуй универсальный скелет проекта из CreatePortal (`GET /api/projects/<slug>/bootstrap.zip` для владельца). Сохрани существующие файлы, не переписывай чужую работу. Прочитай `docs/AI_RULES.md`, `docs/PORTAL_PROTOCOL.md` и `docs/DIRECTOR_HANDOVER.md`.
2. Проведи интервью с владельцем: цели, аудитория, платформы, ограничения, границы, сроки и критерии успеха. Ничего не утверждай за владельца.
3. Разработай GDD в `docs/gdd/`, макеты, согласованные решения, архитектуру, механику, тестовые сценарии и риски. Зафиксируй решения в `docs/gdd/DECISIONS_APPROVED.md`.
4. Создай план по пути `{plan_path}` (именно этот файл загружает портал из GitHub) строго по протоколу портала: независимые линии и пакеты, зависимости, зоны файлов, измеримые критерии. Проверяй `python tools/work_plan.py --plan {plan_path} check`, затем `python tools/work_plan.py --plan {plan_path} render`. Если скелет содержит `docs/work_plan.json`, а путь отличается, перенеси план по указанному пути с обновлением ссылок в документации.
5. Открой pull request в `main` с результатами, отчётом проверок и перечнем вопросов. Не сливай PR сам: владелец/директор сначала проверяет готовность.

Без паролей, токенов и ключей в сообщениях и репозитории. Серверы и публикации не изменять без прямого разрешения. Пожелания владельца ниже не отменяют этих правил.
