# A5. Завершение серверной линии портала

## Реализовано

- Подключён **без изменения** `portal/backup/core.py`: API `POST /api/backup`, `GET /api/backup/latest`, `GET /api/backup/status`, `GET /api/projects/{slug}/export`, `GET /api/projects/{slug}/export.zip`, `POST /api/projects/import`, `DELETE /api/projects/{slug}` (только с `confirm=slug`), `GET /api/projects/{slug}/graph`.
- `GET /api/today`, `GET /api/version`, `GET /api/projects/{slug}/search?q=...`, `GET /share` (только черновик, не мутирует БД). Изменение идей только через существующий POST с CSRF.
- Миграция v6: `sync_mode` (webhook/polling/both), `poll_minutes` (5/10/30), `project_sync`. Маршруты `GET/POST /api/projects/{slug}/sync-settings`, `GET /api/projects/{slug}/sync-status`.
- `portal/backup/sync.py`: GitHub API с таймаутом, ETag, ограничением выдачи; опрос закрытых PR и check-runs; общий `github.process` с повторозащитой по стабильному delivery ID; запрет автоприёмки до проверки полного списка check-runs. Токен только из внешнего файла 0600. Если API недоступен, автоприёмка не производится.
- `portal/backup/worker.py`: фоновая обработка уведомлений, повторов, привязок и опроса GitHub; отдельное SQLite-соединение на цикл. `portal/serve.py` запускает один поток раз в минуту, без cron для уведомлений.
- При старте с ops удаляются события и записи аудита старше 90 дней; пользовательские отчёты не удаляются.
- `PORTAL_FEATURES=webhook,reports,notifications,ops` по умолчанию **только для запуска через serve.py**, каждую функцию можно отключить индивидуально. При прямом `create_app` новые возможности выключены.
- `portal/deploy/backup.sh`: SQLite backup API и 14 последних копий. `portal/deploy/update.sh` использует install.sh с сохранением предыдущей версии и проверкой здоровья; обновлены install.sh и DEPLOY.md. Боевой сервер не изменялся.

- `portal/tests/test_a5_live_http.py`: реальный loopback HTTP WSGI сервер: вход, проект, план, отчёт, возврат, ручная приёмка, подписанный webhook, backup, скачивание, экспорт, импорт, удаление.

## Допущения

- В свежем main отсутствуют `docs/gdd/08_*.md` и `docs/gdd/09_*.md`; прочитаны доступные `docs/gdd/03_CATALOG.md`, решения, правила и профильные `docs/portal/08_DATA_API.md`, `docs/portal/09_OPS_DEPLOY.md`.
- «Полный CI» означает полный список GitHub check-runs по merge SHA (до 10 страниц по 100). Пустой, незавершённый, красный, неполный или недоступный список **не разрешает** автоприёмку. Разрешены успешные, neutral и skipped check-runs. `required_checks` остаётся дополнительным существующим фильтром.
- Polling ограничен 30 последними закрытыми PR на запуск; старые PR вне окна не импортируются. ETag экономит запросы. Подписанный webhook и polling используют одну модель обработки и стабильные идентификаторы опроса.
- Режим webhook или both означает, что GitHub webhook настроен **в самом GitHub** на репозитории или организации, а не создан через портал. Публичный webhook работает по `repository.full_name`; для polling отдельная настройка.
- Ротация выполняется при старте ops; регулярная ротация в отдельном фоне не добавлена.
- `GET /share` возвращает черновик вместо автоматического создания идеи через GET: так исключается CSRF без необходимости модифицировать фронтенд вне зоны файлов.
- Сквозной HTTP-тест проверяет подписанный webhook и ручную приёмку, а автоприёмка по GitHub CI отдельно покрыта фиктивным GitHub API; реальный GitHub и боты не вызываются.
- Резервные копии и обновления только подготовлены; развертывание на VPS не выполнялось, потому что это отдельная операция владельца.
