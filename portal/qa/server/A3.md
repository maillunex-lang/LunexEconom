# A3. Отчёты, приёмка, доработка и метрики

## Реализация

- Введена отдельная миграция v4 для отчётов и чек-листов, с составными ключами `(project_slug,pkg_id)`; старые данные не удаляются.
- За флагом `reports_enabled=False` добавлены `GET/POST /api/projects/{slug}/tasks/{id}/report` и `/review`; события доступны в `GET /api/projects/{slug}/events`.
- Отчёт содержит текст до 20 000 символов и необязательную ссылку на PR GitHub; входящие данные и размер JSON проверяются.
- Чек-лист хранит список пунктов и булевы отметки, статус CI, замечания и число возвратов. Возврат с непустыми замечаниями из `submitted` переводит задачу в `issued`, очищая дату сдачи.
- `POST /api/projects/{slug}/status` при принятии проверяет полный чек-лист и отсутствие красного CI (включая связанные PR), иначе 409 с русским объяснением. `manual=true` разрешает явное исключение и фиксируется в журнале без сохранения текста или секретов.
- `GET /api/metrics` и `GET /api/projects/{slug}/metrics`: принято за 7 дней, среднее время выдача→сдача и сдача→приёмка в секундах, доля задач с возвратом, ожидающие приёмки, красные CI.
- Все маршруты требуют сессию, POST также CSRF. В журнал пишутся только безопасные поля; тексты отчётов и замечаний остаются в отдельных таблицах.

## Допущения

- `docs/gdd/08_*.md` отсутствует в свежем `main`; прочитан `docs/gdd/06_RETAIL.md`, профильный `docs/portal/06_REPORTS_REVIEW.md`, `docs/gdd/DECISIONS_APPROVED.md` и `docs/AI_RULES.md`. Спецификация портала приоритетна для A3.
- Новый функционал выключен по умолчанию (`reports_enabled=False`), чтобы сохранить совместимость со старыми клиентами и тестами. Для включения требуется отдельная явная конфигурация при запуске приложения.
- Состояние CI без данных (`unknown`) не считается красным; блокируется только `failure`/`failed`/`red`. Для принятия без полного чек-листа используется явный `manual=true`.
- Ручная приёмка фиксируется в `audit` и `events`, без произвольного текста причины, чтобы исключить утечки секретов.
- Метрика «доля возвратов» означает долю уникальных задач с хотя бы одним возвратом среди задач, имеющих историю статуса или проверки; длительности учитываются только при наличии обоих временных штампов. Время выдача→сдача и сдача→приёмка считается раздельно.
- Шаблон чек-листа из пяти пунктов соответствует документу 06; пользовательские пункты допустимы с ограничением 30 штук.
- Автоприёмка вебхуков остаётся в существующем модуле интеграций и не изменена; флаг A3 влияет на ручной маршрут статусов.
