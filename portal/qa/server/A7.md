# A7. Автоматизация приёмки: сервер и интерфейс

## Реализовано
- Ветка `portal/a7-review-automation` от свежего `main`. `portal/review/**` и его 35 эталонных тестов **не изменены**.
- Миграция SQLite v9: `project_a7_settings`, `task_review_runs`, `task_returns`, `project_lessons`, `project_prompt_library`, `task_auto_merge`, `projects.project_type`.
- GET `tasks/{id}/review`: GitHub PR files с пагинацией, stats, diff с ограничением 2 МБ, read-only токен 0600, зона из `lanes.zone + zone_extra`, общие файлы из `rules`, CI из `pr_links`, отчёт и чек-лист из A3. `engine.review` и `returns.reasons_from_review`, журнал светофора и события. Сетевая ошибка и неполные данные всегда как минимум жёлтые. Проверка при сдаче, изменении чек-листа и GitHub PR/CI событиях.
- `auto_merge` по умолчанию выключен, kill switch включён. Отсрочка от 10 до 1440 минут, отмена владельцем, worker только при `PORTAL_REVIEW_A7_ENABLED=1` и включённом webhook/launch. Отдельный merge-token 0600, проверка актуального head SHA, основной ветки, mergeability, полных GitHub check-runs и повторный светофор. Squash с SHA precondition; при успехе запись в аудит/события, принятие, библиотека удачных промптов, события готовности следующих задач и уведомления. При неуспехе попытка отменяется, слепого повтора нет.
- `GET conflicts` на основе выданных и готовых задач и последних известных файлов PR, подсказка при выдаче. `GET /api/return-templates`, `POST /tasks/{id}/return` с шаблонами, заметкой, промптом, историей возвратов. `GET/POST/DELETE lessons`, проверка секретов `knowledge.add`, предложения после двух повторов, знания и похожие примеры в новых промптах.
- Синхронизация плана после merged PR webhook по `plan_path` каждого проекта; фоновый опрос A6 тоже учитывает `done=accepted`. Каталог 4 типов проектов, `project_type` в мастере и стартовый план, адаптированный ZIP-скелет с `gdd_outline`.
- UI: светофор с раскрывающимися пунктами, возврат с чипсами и копированием промпта, блок конфликтов, отдельная вкладка «Знания проекта», настройки авто-слияния, отсрочки и kill switch, выбор типа проекта. Отступы и темы сохраняются.

## Допущения и ограничения
1. В текущем `main` отсутствует `docs/gdd/10_*.md`; прочитаны `docs/gdd/06_RETAIL.md`, `docs/portal/10_ROADMAP_ACCEPTANCE.md`, `docs/gdd/DECISIONS_APPROVED.md`, `docs/AI_RULES.md`. Макеты `docs/mockups` просмотрены по каталогу; отдельного макета A7 нет.
2. GitHub API и merge-токены **не подключались в реальности**, проверены только подменёнными API. Никакого реального PR не сливали. Включать auto_merge в production до отдельной проверки с тестовым репозиторием не рекомендуется.
3. «Зелёный» требует заполненного чек-листа и отчёта, успешного CI, тестов и полного диффа. Неизвестное состояние GitHub = жёлтый; красный блокирует даже ручную приёмку через статус. Отсрочка минимум 10 минут.
4. При отключённом A7-флаге новые API возвращают 404, фоновое слияние не запускается. UI для выключенного флага может показывать сообщение «функция недоступна» вместо скрытия блока.
5. При нескольких проектах с одинаковым GitHub repo, но разными plan_path, A7 merged webhook обновляет каждый путь отдельно; старый A5 push-webhook использует первый путь. Это отдельно описано в A6.
6. После слияния задача помечается принятой; следующая задача лишь появляется как готовая к выдаче, автоматическая выдача исполнителю запрещена.
7. Библиотека и знания хранятся JSON в SQLite, а не в GitHub; в логах сохраняются только безопасные метаданные, не токены и не содержимое diff.
