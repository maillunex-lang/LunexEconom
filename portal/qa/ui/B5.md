# B5. Аудит доступности интерфейса CreatePortal (в рамках B4)

## Проверено
- Интерфейс использует `textContent` для пользовательского текста и сообщений сервера, без вставки HTML из API.
- Для новых кнопок задан `title` и `aria-label` через общую функцию `btn`; минимальная высота 44 px. Для новых полей `input`, `select`, `file` есть aria-label или текстовая подпись.
- Фокус с клавиатуры усилен контуром 3 px и отступом 3 px; прокручиваемый граф доступен через Tab (`tabIndex=0`, `role=region`, `aria-label`).
- `prefers-reduced-motion: reduce` отключает анимации и переходы; сохранены светлая/тёмная темы и мобильные safe-area отступы.
- Ошибки и загрузка новых экранов выводятся текстом с `role=status`; операции изменения данных не совершаются при 404.

## Ограничения аудита
- Автоматический измеритель WCAG контраста и полноценная клавиатурная проверка всех прежних компонентов не запускались; нельзя утверждать, что WCAG AA доказан.
- В исходных B1–B3 остаются обработчики событий, заданные через JavaScript свойства `onclick`, но не inline HTML-атрибуты. CSP nonce сохранён.
- Десктопная область деталей CSS требует отдельной визуальной приёмки директором, особенно при очень длинных промптах.
- Автоматизирован сквозной сценарий создания проекта, плана, отчёта и приёмки; резервная копия не выполняется до появления A5. Не отмечать этот критерий как выполненный.
