# B2. Настройки, аудит, PR и CI

## Реализовано

- Страница «Настройки»: секции GitHub, уведомления, копии, исполнители с честной маркировкой «Скоро»; смена пароля с проверкой текущего, длины нового (14+) и совпадения; двухшаговое подтверждение завершения всех сеансов с текущим паролем; журнал аудита с датами, состояниями загрузки, пустого ответа, ошибки и повтора.
- Настройки проекта доступны на ПК и телефоне. Переключатели «Автоприёмка при слиянии» и «Требовать чек-лист» читаются и сохраняются только через GET/POST `/api/projects/{slug}/settings`, начальное значение не выдумывается. При недоступном серверном API элементы заблокированы и отображена ошибка. Изменение ветки, состава обязательных CI и удаление проекта недоступны: эти функции не имеют разрешённого контракта реализации в рамках B2.
- Панель задачи условно показывает PR, разрешённую ссылку GitHub, SHA, CI и результаты проверок. Данные из `packages[].pr/ci` и `state[id].pr/ci` являются необязательными. Без них блока нет. Если сданная задача ждёт CI, видна соответствующая метка. Метка «Принято автоматически: слито в main, CI зелёный» показывается при статусе `accepted`, признаке слияния, успешном CI и серверном признаке auto_accept. Есть подсказка «Вернуть из архива».
- Все новые текстовые значения отображаются через `textContent`, PR-ссылки допускают только HTTPS github.com с путём репозитория и `/pull/NUMBER`; никаких секретов или внешних библиотек. Новые кнопки имеют подсказки, минимальная высота 44 px. Серверные файлы, базы и сервисы не изменялись.

## Допущения

1. В `main` отсутствует `docs/gdd/07_*.md`. Прочитаны имеющиеся `05_*.md`, `06_*.md`, `DECISIONS_APPROVED.md`, `docs/AI_RULES.md` и профильные документы/макеты портала. Не создавали и не изменяли `docs/**` из чужой зоны.
2. В первоначальном `main` не было маршрутов A1; перед сдачей влит новый `main`, где `/api/password`, `/api/sessions/revoke`, `/api/audit` уже реализованы с включённым по умолчанию `security_v2` на уровне приложения. Смена пароля принимает обновлённый CSRF, сброс всех сеансов требует текущего пароля, журнал использует `entries`. `/api/projects/{slug}/settings` и поля PR/CI пока отсутствуют; успешный путь настроек проекта проверен моками. Пароль передаётся полями `current_password` и `new_password`, а сброс всех сеансов передаёт `current_password`; запросы идут с CSRF.
3. Для GET настроек принимаются объект настроек или `{settings:{...}}`; для журнала массив или `{events:[...]}`/`{audit:[...]}`. При неизвестной форме клиент показывает пустое состояние. Удаление и смену основной ветки не реализуем до серверного API.
4. Ссылка PR отображается только при строго проверенном URL GitHub, остальные строки PR/CI считаются недоверенными и выводятся как текст. Для метки автопринятия нужен явный серверный флаг, одного лишь зелёного CI и слияния недостаточно, чтобы не вводить директора в заблуждение.
5. Переключатели по умолчанию выключены и не доступны для изменения до получения серверных настроек. Клиент не включает автоприёмку самостоятельно.
6. Артефакты и проверки B1 не изменены. Сценарий B2 отдельный, все изменения строго в своей зоне.
