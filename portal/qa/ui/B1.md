# B1. Мобильная доска, вариант 4

## Реализовано

- На ширине до 720 px: сегмент «Сервер · A», «Клиент · B», «Обе»; независимый выбор линии без изменения серверных данных.
- Плашка «Параллельно» показывает приоритетную задачу другой линии (приёмка, работа, готовность) и переводит к ней.
- Вертикальная лесенка: завершённые задачи свёрнуты с галочками, активные показывают статус и кнопки, будущие приглушены. Для «Обе» шаги двух линий отображаются в двух вертикальных колонках.
- Мобильная панель быстрых действий фиксирована над нижней навигацией. Статусы меняет существующий API с CSRF; приёмка подтверждается в панели задачи. Подсказки и aria-label используются на новых кнопках.
- При ширине от 721 px остаются прежние «Дорожки» и остальные элементы большого интерфейса.
- Собственный Playwright-засев создаёт временную SQLite, временные учётные данные существуют только внутри теста; реальные аккаунты и БД не используются.

## Проверки

- `python3 -m unittest discover -s portal/tests -q`: 22 теста, OK.
- `node` проверка JS-синтаксиса: OK.
- `python3 portal/ui_tests/shots.py --output portal/ui_tests/shots`: 6 снимков, браузер без неожиданных console errors и page errors; начальный 401 от `/api/me` до входа ожидаем.
- 390×844 и 1440×900 в двух темах; мобильный режим «Обе» в двух темах; проверка отсутствия горизонтального переполнения.
- Запуск Chromium на Ubuntu 26.04 требует совместимой сборки Playwright и недостающих библиотек, вынесенных в отдельное окружение рабочего каталога (не в репозиторий).

## Допущения

- В исходном `main` нет `docs/gdd/07_*.md` и `docs/gdd/11_*.md`: прочитаны профильные `docs/portal/07_UI_UX.md` и `docs/portal/11_MOBILE_PWA.md` целиком. `docs/gdd/03_CATALOG.md`, `docs/gdd/DECISIONS_APPROVED.md`, `docs/AI_RULES.md` прочитаны.
- Использован существующий API статусов, без новых серверных функций и флагов. Новый режим включается только при ширине не более 720 px по утверждённому проекту.
- «Текущими» считаются выданные, сданные и готовые к выдаче задачи, поскольку параллельные задачи могут быть активны одновременно.
- В режиме «Обе» нижняя панель привязана к приоритетной задаче линии A (линия B доступна через собственную карточку).
- Ожидаемый 401 начальной проверки сеанса не рассматривается как ошибка JavaScript после входа.
- Требование изменять `.github/**` противоречит заданной зоне файлов, поэтому интеграция снимков вынесена в самостоятельный скрипт, готовый к запуску в CI; workflow вне разрешённой зоны не изменён.
