# Башкирия: Мёд и Нефть · LunexEconom V2

Многопользовательский **экономический симулятор для Android** на карте Республики Башкортостан. Игрок строит компанию: выращивает сырьё, перерабатывает, торгует, расширяется по городам. Экономика считается на сервере круглосуточно: **1 игровой месяц = 24 реальных часа**, 1 игровые сутки = 48 минут, граница месяца в 09:00 по Уфе. Игровые рубли ненастоящие и не имеют отношения к реальным деньгам.

Репозиторий начинается с нового корневого коммита (V2). Прежняя версия лежит в ветке `archive/v1` и теге `v1-archive`; данные и аккаунты V1 не переносятся.

Сайт и скачивание: **rikagro.ru/lunexeconom** (публичный запуск после приёмки беты).

> **Для новых игр:** [библиотека исходников](docs/SOURCE_LIBRARY.md), [карта модулей](docs/MODULE_INDEX.md), [каталог идей](docs/REUSE_CATALOG.md). Это справочник по коду, а не новый GDD.

## Как устроена работа (быстро)

- Всё проектирование делает директор: GDD в [`docs/gdd/`](docs/gdd/README.md), решения владельца в [`DECISIONS_APPROVED.md`](docs/gdd/DECISIONS_APPROVED.md), макеты в `docs/mockups/`, симуляторы в `tools/sim/`.
- Реализуют исполнители, **две независимые линии** одновременно: **A (сервер)** и **B (клиент, на моках по контракту)**. Зоны файлов не пересекаются, проверяется автоматически.
- Команды: `python tools/work_plan.py next` (что выдавать), `python tools/work_plan.py prompt A1` (готовый текст задания), `python tools/work_plan.py set A1 done` (отметить), `python tools/work_plan.py check` (проверка плана).

## Структура репозитория

- [`server/`](server/): Python 3.12+, PostgreSQL 16, независимые модули и реестр маршрутов и тиков (`platform`, `ledger`, `clock`, `catalog`, `world`, `enterprises`, `supply`, `market`, `retail`, `sales`).
- [`client/`](client/): Godot 4.7.2, Android, горизонтальный режим (экраны, карта, обновление, загрузка ресурсов, плагин установки).
- [`web/`](web/): статический лендинг с последней проверенной сборкой APK, дорожной картой и мобильной панелью администратора (`web/admin/`).
- [`portal/`](portal/): портал проектов CreatePortal (Python, SQLite): доска задач, мастер новых проектов, протокол для ИИ.
- [`ops/`](ops/): автообновитель сервера (с проверкой CI и откатом), скрипты развёртывания и выкладки релизов (`ops/partc/`).
- [`tools/`](tools/): проверки каталога, мира, предприятий, сайта; подпись манифестов; сборка пакетов ресурсов; эталонный симулятор экономики (`tools/sim`).
- [`docs/`](docs/): документация (см. ниже).
- `.github/workflows/`: проверки сервера, клиента, сайта, сборка Android, релиз.

## Запуск сервера локально

Нужна **отдельная** PostgreSQL 16 для разработки. Никогда не подключайте боевую базу.

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -r server/requirements.txt
export LUNEX_DATABASE_URL='postgresql://lunex_dev:ВАШ_ЛОКАЛЬНЫЙ_ПАРОЛЬ@localhost:5432/lunex_v2_dev'
python -m server.game_server
# GET http://127.0.0.1:18777/health
```

Миграции применяются при старте и проверяются по SHA-256. Основные параметры окружения: `LUNEX_DATABASE_URL`, `LUNEX_PORT`, `LUNEX_ADMIN_TOKEN`, `LUNEX_THREADS`, `LUNEX_POOL_MIN`, `LUNEX_POOL_MAX`, `LUNEX_TICK_INTERVAL`.

## Проверки

```bash
export LUNEX_TEST_DATABASE_URL='postgresql://lunex_ci:ВАШ_ПАРОЛЬ@localhost:5432/lunex_v2_ci'
export LUNEX_DATABASE_URL="$LUNEX_TEST_DATABASE_URL"
python -m unittest discover -s server/tests -v            # сервер (нужна изолированная PostgreSQL)
python -m unittest discover -s ops -p 'test_*.py' -v      # автообновитель
python -m unittest discover -s tools/tests -v             # инструменты, строки, сайт
python tools/validate_catalog.py && python tools/validate_world.py && python tools/validate_enterprises.py
python tools/check_website.py
python tools/work_plan.py check                           # план работ
# клиент (Godot 4.7.2): godot --headless --path client -s tests/smoke.gd
```

Без `LUNEX_TEST_DATABASE_URL` интеграционные тесты **пропускаются**, это не значит, что они прошли. CI всегда задаёт изолированную базу.

## Как ведётся разработка

- Проектом руководит директор (ИИ): пишет спецификации и задания, принимает работу.
- Исполнители (ИИ-ассистенты) работают в отдельных ветках и не меняют `main`. Слияние в `main` выполняет директор после приёмки (постоянное разрешение владельца); изменения VPS, ключей, вайп мира и финальное переключение V1/V2 только по прямой команде владельца.
- Каждое задание принимается по проверкам: тесты на изолированной PostgreSQL, CI, зона файлов, отчёт по [`docs/AI_RULES.md`](docs/AI_RULES.md).
- Деньги и расчёты только целыми числами (bp, промилле), без `float`. Все числа баланса помечены `balance: draft` до общей настройки.
- Секреты (ключи подписи, пароли, токены) никогда не хранятся в репозитории.

## Безопасность и развёртывание

Боевой сервер обновляется автоматически только из проверенных коммитов `main` и откатывается при сбое проверки здоровья. Изменения инфраструктуры выполняются только по команде владельца по скриптам из `ops/partc/`. Релизы подписываются автоматически (владельческий сертификат APK и отдельный ключ манифеста, оба секретами GitHub, на сервере приватных ключей нет), сервер раз в 30 минут проверяет подпись и SHA-256 и выкладывает новую сборку на сайт с откатом при сбое.
